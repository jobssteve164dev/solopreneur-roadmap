# Blog 投影契约

SZLKBlog 是文章与发布版本的权威；本产品保留自己的渲染、URL、语言关联和 SEO。项目为 `solomap`，站点为 `solomap`，正式 Worker 为 `solomap-website`。

## 唯一运行路径

- `BLOG_PROJECTION` 绑定 SQLite Durable Object，类名 `BlogProjection`，对象名 `blog:solomap`。
- `src/blog-projection-store.js` 与另四个 Worker 消费者使用同一份增量存储实现。修改共享实现时必须同步五仓并运行各仓真实行为回归。
- 正文按完整规范化内容的 SHA-256 存储；完整发布清单在 SQLite 事务内切换，同时保留上一成功版本。相同正文不重复写入，清理仅涉及两版均不引用的派生正文。
- 生命周期事件按项目和站点校验，权威拉取、验证、激活在同一对象内串行。已成功处理的最近 200 个事件持久化去重；超过窗口的重投仍按内容比较，不能重写历史全集。
- 过期通知必须协调到当前权威快照并登记去重。空权威快照可以移除最后一篇文章。权威拉取、内容校验或事务失败保留上一完整快照。
- 页面仅消费已激活投影；普通访问不执行迁移或权威回填。正式代码不得读旧 D1/KV/旧 DO 快照，也不得双写或运行时回退。

## 切换前置条件

当前源码改变了存储入口，不能直接部署到尚未预填的新对象。生产切换前必须沿既有 Wrangler 发布路径准备一次性迁移制品，保持现有页面服务，填充并验证新对象，再发布本文件定义的最终制品。准备制品还必须将窗口内的合法生命周期通知同步到新投影，两个投影成功后才确认通知；失败通过既有 outbox 重试。迁移入口、临时同步与旧读取逻辑不得进入最终制品。

正式命名工具读取的 2026-09-05 已发布目录为 26 篇；这只是本次审计基线，切换前须重新核对精确 `post_id + locale + slug + published_version_id + content_digest`，不能只核对数量或使用草稿摘要替代已发布版本。历史内容、地址、发布时间及语言关联必须守恒。

仅使用既有项目凭据和回调鉴权。本次已获批使用同账户 CF Token 成对轮换接收端与 SZLKBlog 发送端的现有回调密钥；密钥只通过 Wrangler secret bulk 注入，不进入源码或日志。发布工作流必须保留 CF 上的当前值，不得覆盖回历史副本。旧表、键和对象保留封存；物理删除必须另有精确清单授权。

## 验证

在本产品目录运行：

```sh
npm test && npx wrangler deploy --dry-run
```

回归涵盖正文增量写入、重复事件、重启后去重、新旧通知、空快照、事务失败与最后成功页面。共享引擎另在 SoloMap website 的 workerd 测试中验证最终打包代码的 SQLite 计量；1000 篇文章中改 1 篇的实测为写 3 行，重复事件写 0 行，同内容新事件写 1 行。这是本地引擎证据，不是生产账单结论。

存储迁移验收同时覆盖数据与可见行为：除逐篇身份、版本和内容外，必须对照旧读取路径验证列表排序、同值排序规则、分页、各语言页面、sitemap 与语言链接；SQL 的 ORDER BY 等隐含行为必须在新读取层显式保留。全文字段一致不能替代接口和渲染结果对照。

生产验收仍需核对精确 Worker 制品、全部文章目录与 URL、sitemap/canonical/语言关联、生命周期状态及旧读取入口退出；本地测试和 dry-run 不替代这些证据。首个非预期生产结果出现后停止新增写入，只读定位同一对象和请求链。
