# 本地优先加载链路审计（2026-10-21）

验收依据：[本地优先加载交互体验基线](local-first-loading-interaction-baseline.zh.md)。审计起点为 `b2913999e08a2eb6f63c17e6c0a472a92eacda80`（0.0.616）。目标是修正加载、刷新和启动的根因，不是代用户恢复某条生产对话。

## 现场证据与结论边界

- 正式诊断中，AIQ 续聊交互 `e65163ca44617205` 在 3ms 创建终端、255ms 进入停止旧运行阶段，约 535559ms 后失败；没有进入备份、准备和正式命令投递阶段。因此“终端已出现”不能作为续聊成功，卡点位于旧运行停止路径。
- 已有冷启动核心完成记录为 20325、27034、26460、19521、37314ms，均超过 15 秒。旧的单元测试通过不能证明现场达标。
- **Observed in code / 隔离复现：** 加载链存在多处错序；共享运行器也能在无人读取 stdout/stderr 管道时卡住停止收口。两类问题分别修正、分别验证。
- **Inference：** 管道背压能解释一种旧运行无法退出的机制，但没有取得该 AIQ 旧 wrapper 的内部等待栈，不能据此断言它就是这次生产阻塞的唯一原因。
- 审计没有恢复 AIQ 对话、强杀生产进程、直接打开生产数据库或重载用户窗口。新代码不会热替换已经运行的旧 wrapper。

## 发现、修正与回归

| 路径 | 已证实的问题 | 当前修正及证据 |
| --- | --- | --- |
| 冷启动与项目切换：`extension.ts / ensureSyncEngine` | 已知项目的 CSV 首屏仍排在 Runtime 健康确认之后，本地卡片等待后台初始化。 | 已有注册缓存时先构造项目引擎并推送 CSV，数据库初始化与历史补全随后进行；缺少注册数据时仍经正式 Runtime 读取，不新增数据旁路。延迟健康确认回归验证首屏不被阻塞。 |
| 设置：`extension.ts / settings.get` | 冷启动设置必须区分已保存值与未水合值，不能用默认空对象宣布完成。 | 快照路径等待正式设置水合并复核数据根；核心完成标记等待设置、任务、最近对话全部到达。实际宿主断言保存的全局指令可见。 |
| 项目选择：两个 Webview、`selectProject`、`sendProjectSelection` | 前端没有完整消费权威选择事件；后台设备状态可能覆盖新选择；A→B→A 和 B→A→B 中旧响应可重新获得提交权。 | 每次点击独立 interactionId，宿主原样确认并带 generation；待确认阶段阻止旧作用域数据提交；拒绝选择也明确回执并重新投递当前数据。后台恢复只在尚无用户选择时执行。 |
| 最近对话：`sidebarProvider.ts` | 缓存写入的 await 之后缺少复核，较旧 Running 快照可以覆盖已经完成的状态；切换时清除共享读取会造成重复读取。 | 缓存响应后再次复核项目代次、请求身份与账本修订；只撤销旧订阅提交权，保留同项目 single-flight。真实延迟写入回归覆盖 Completed 不回退，A→B→A 只读取一次。 |
| 路线图 Solo / Flow 标签恢复 | 乐观激活目标项目时先读取历史，然后才发出项目选择；宿主读取旧项目，回包被丢弃后 Solo 保持 loading。 | 待确认时不发历史/Flow 请求，也不设置 Solo loading；匹配确认后恢复一次当前标签读取，请求携目标项目。回归覆盖切回曾使用的标签、错误确认及旧代次回包。 |
| 项目组合与后台刷新 | 空的恢复扫描、授权增强和仅选择变化可能重新触发整批初始化；普通渲染会重排每日复核轮询。 | 只有真正导入当前数据根才刷新本地注册；授权增强仅推本地字段；仅项目清单内容变化才重启整批加载。轮询由明确的运行状态事件维护，render 只消费状态。 |
| 运行结束刷新 | refresh 结算重新读取完整历史，Session Closed 又重复推同一结果。 | refresh 使用跳过全量历史的初始化，复用结算刷新结果；提交前复核引擎和项目。业务上仍需要历史的其他结算效果保持原路径。 |
| 相同节点和会话快照 | 相同节点仍可重建可操作 DOM；重开 Sidebar 时先到的 gen7 数据会按前端初始 gen0 登记完成，永久等不到核心完成。 | 相同节点签名跳过重建；完成标记使用消息源代次。真实脚本覆盖两种到达顺序，真实浏览器覆盖鼠标按下期间刷新、键盘操作、草稿、附件与输入法。 |
| 终端命令投递：`terminalCompatibility.ts` | 固定 5 秒竞速可能在 Shell 尚未就绪时发命令。 | 支持 processId 的宿主等待真实就绪 Promise，同终端保持串行投递；模拟推进 6 秒仍未就绪时不投递，就绪后提示与正式命令各投递一次。旧宿主兼容路径保留。 |
| 运行停止：`runAgentProcess.ts` | 管道显示使用 Node stream 写回调时，停止虽唤醒等待，挂起的 WriteWrap 仍能阻止 wrapper 自然退出。 | POSIX 管道/套接字使用已有非阻塞描述符写入，TTY 保留自有非阻塞描述符；日志先正式落库再显示。真实 stdout/stderr 背压回归验证自然退出、session-close、原 turn 结果及封存后读取的完整日志。没有跳过停止等待或提前封存。 |
| 编辑器配置：`tsconfig.json / projectRegistry.ts` | 编辑器 TypeScript 6.0.3 报旧 node10 解析配置弃用错误；改 Node 模式后动态导入还必须兼容最终 CommonJS 运行行为。 | 使用 node20 / node16，去除旧 ignoreDeprecations；延迟导入带 `.js` 并通过 default 取得实时 CommonJS 导出。仓库编译器与编辑器编译器分别验证。 |

Actions、Issues 的 Agent 按钮继续使用各自 launchActionId 的完成回执；项目选择屏障没有拦截这些回执，也没有用禁用按钮掩盖刷新问题。

## 尚未证明的范围

- 这些计时来自隔离的 Linux code-server 验收，不能替代 AIQ 生产窗口的新版本端到端记录，也不能推广为 Windows 已实测。
- 双项目切换的 5 秒时限、大图切换的 10 秒时限尚无本轮真实宿主计时；现有证据覆盖代码路径、延迟/乱序回包和状态不串项目。不能据此宣布基线所有项目均已合规。
- 现场旧 wrapper 的具体等待栈仍未知；不把“修正一种已复现停止阻塞”写成“现场旧运行已恢复”。
