# SoloMap 一人公司战略金字塔视图设计文档

**讨论日期**: 2026-06-03  
**提出者**: 用户  
**设计目标**: 为独立开发者提供一人公司战略驾驶舱，而非重复单项目路线图或今日执行排序  
**目标版本**: Pro 功能 (P1)  

---

## 核心问题与机会

### 现状
- SoloMap 现在帮助用户管理**单个项目的路线图**
- 侧边栏的**今日安排**已经在帮助用户判断今天先处理什么
- 项目卡片已有该项目的路线图大图入口，负责进入项目推进驾驶舱
- 用户已有多项目经营需求，但缺少**一人公司战略驾驶舱**

### 提出的需求
> "我们侧边栏项目卡片上有打开，底部还有个打开路线图大图大按钮，我在考虑增加一个类似独立开发者项目总览金字塔大图视图，你觉得可行吗？"

### 深化的提问
> "从一人公司或者一个成熟的可复利系统的独立开发者完整运营生命周期来看，我们这个金字塔视图需要包含哪些设计？"

### 本轮确认的定位

金字塔视图不是项目总览、不是任务推荐、不是指标大盘，而是独立开发者或一人公司的**战略驾驶舱**。

SoloMap 的三个驾驶舱分工如下：

| 产品区域 | 驾驶舱类型 | 回答的问题 | 入口 |
| --- | --- | --- | --- |
| 侧边栏今日安排 | 今日执行驾驶舱 | 今天先处理哪几件事 | 侧边栏首屏 |
| 单项目路线图大图 | 项目推进驾驶舱 | 这个项目如何从当前状态推进到交付 | 项目卡片内 |
| 战略金字塔视图 | 一人公司战略驾驶舱 | 时间、项目、能力、收入、市场信誉是否形成可复利系统 | 侧边栏底部 |

入口原则：

- **项目级入口归项目卡片**：项目路线图大图只从项目卡片进入。
- **组合级入口归侧边栏底部**：侧边栏底部只保留战略金字塔入口。
- 金字塔可以影响今日安排的排序权重，但不能变成另一个“今天先做什么”面板。

## 金字塔设计框架

### 一、战略背景：独立开发者的生命周期

一人公司不是"多个项目的集合"，而是一个动态演进系统：

```
建立信誉 → 开发能力 → 获得收入 → 形成可复利收入 → 放大可复利系统 → 自由选择方向
```

金字塔需要回答的核心问题：

1. **能力积累层**：我学到了什么？这些能力能跨越哪些项目复用？
2. **市场信誉层**：用户在哪里发现我？我的产品有多少交叉转化空间？
3. **收入多元化层**：我靠什么赚钱？收入来源有多健康？
4. **个人可持续性**：我投入 vs 回报的比例如何？是否走向自动化？
5. **战略取舍层**：我应该加码、收缩、暂停、转向，还是孵化新方向？

金字塔不回答“今天点哪里开始”，这个问题由侧边栏今日安排回答。金字塔回答的是“未来几周到几个月，我的一人公司结构是否健康”。

## 金字塔的 5 层架构

### 顶端：自由与品牌（目标状态）
```
⭐ 自由选择 & 个人品牌
```

**指标**：你的个人品牌价值、知名度、选择权

**信号**：
- 媒体提及、演讲邀请
- 社区声誉、引用与推荐
- 独立定价能力
- 合作机会选择权

**示例**：
- 在社区被认可为某领域专家
- 无需主动营销就有 inbound 需求
- 能对不符合价值观的需求说"不"

---

### 第四层：可复利收入系统（关键指标）
```
可复利收入系统 (目标：≥30% 被动/半被动)
```

**分类维度**：
- **产品订阅**（SaaS、持续订阅费）
- **数字资产**（教程、模板、代码库）
- **联盟与佣金**（推荐、广告、合作分成）
- **即时咨询或培训**（workshop、一对一指导）
- **品牌赞助与合作**

**健康指标**：
- 可复利收入占比 ≥ 30%
- 至少 2 个独立收入来源
- 单一来源 < 60%（避免过度依赖）

**风险信号**：
- 🔴 可复利收入 < 20%（过度依赖服务/咨询）
- 🔴 新客户获取下降（趋势下行）

---

### 第三层：市场覆盖与信誉（生态位）

#### 维度 A：发现渠道多样性
```
用户从哪里发现你的产品？
├─ 产品搜索（Product Hunt、Indie Hackers）
├─ 社区推荐（Twitter、Reddit、GitHub）
├─ 官网 SEO & 内容营销
├─ 邮件列表与社群
└─ 企业/B2B 渠道
```

**健康状态**：至少 3 个主要渠道活跃

#### 维度 B：市场信誉与用户反馈
```
你在市场中的位置
├─ 产品评价（好评率、评论数、用户满意度）
├─ 用户反馈信号（需求热度、支持负担、流失率）
├─ 竞争位置（与同类产品的差异与优势）
└─ 市场需求确认（用户愿意为什么付费）
```

**指标示例**：
- GitHub ⭐ 数量与趋势
- 产品评分（4.5+ 为健康）
- 月度活跃用户数与增长率
- 用户支持成本（小时/用户）

---

### 第二层：能力系统与产品交付（执行基础）

#### 维度 A：技术能力库
```
你拥有的可复用专业能力
├─ 核心技术栈（我擅长的主要领域）
├─ 可复用工具与模式（代码库、框架、自动化脚本）
├─ 集成与扩展（开放 API、插件生态）
└─ 运营工程化（部署、CI/CD、监控）
```

**评估维度**：
- 市场需求度（该技能在市场上有多稀缺）
- 复用潜力（能用于多少个项目）
- ROI（时间投入 vs 带来的收入）
- 长期战略性（是否值得继续深化）

#### 维度 B：产品交付能力
```
把想法变成产品的能力
├─ 迭代速度（从想法到发布的时间）
├─ 质量稳定性（bug 率、正常运行时间、SLA）
├─ 用户体验质量（界面、文档、上手难度）
├─ 支持响应（客户问题处理速度）
└─ 持续改进（月更新频率、功能完整性）
```

#### 维度 C：项目组合健康度
```
多个项目的分布与平衡
├─ 路线图进度（是否在计划内？）
├─ 阶段分布（Build/Sell/Learn/Improve 是否均衡？）
├─ 长期停滞（哪些项目已经卡住？）
├─ 投入回报比（时间投入 vs 收入）
└─ 战略位置（该项目对整体系统的贡献）
```

---

### 底层：现实锚点与投资库存（战略储备）
```
还有哪些可投资的机会和能力
```

**包含内容**：
- 有多少想法、原型或失败的项目在待命
- 有多少可投资的技术债存在（重构、基础设施改进）
- 有多少已验证的市场需求还没转换为产品
- 个人时间成本与机会成本（年有多少小时可投入）

**用途**：帮助判断未来几周到几个月的资源投向

## 金字塔 UI/UX 设计

### 1. 主屏幕：一人公司战略驾驶舱

首屏不做今日任务排序，也不直接替代项目路线图。首屏只回答经营结构问题：

- 我现在的重心是不是放对了？
- 我的项目组合是在积累复利，还是在制造维护负担？
- 我的收入、能力、市场信誉是否彼此增强？
- 哪些结构性风险会在未来 1-3 个月拖垮我？
- 我应该加码、暂停、收缩、转向，还是孵化新方向？

```
┌────────────────────────────────────────────────────────────┐
│                  一人公司战略驾驶舱                        │
├────────────────────────────────────────────────────────────┤
│                                                              │
│  当前战略状态：集中突破期                                   │

│                                                              │
```

## 关键特性设计

### 特性 1：战略阶段自适应

金字塔不是静态的 5 层。它根据用户的"当前商业阶段"改变呈现优先级：

| 用户当前状态 | 优先显示层 | 关键指标 | 默认问题 |
|---------|-----------|--------|---------|
| 刚起步（1-2 项目） | 底层：能力库 + 市场发现渠道 | 是否能接近第一个付费用户？ | 我应该集中在哪个细分方向？ |
| 成长期（3-5 项目） | 中层：项目组合 + 收入结构 | 哪些项目在积累复利，哪些在消耗注意力？ | 应该加码、收缩还是暂停？ |
| 成熟期（6+ 项目） | 上层：可复利收入 + 系统自动化 | 总投入时间是否可持续？ | 哪些部分应该自动化或委托？ |
| 寻求融资/退出 | 顶层：品牌价值 + 投资组合 | 整体价值和可转让性 | 是否应该产品化、打包或出售？ |

### 特性 2：结构性风险与机会信号

风险信号不等同于今日任务。今日任务由侧边栏安排；金字塔只识别会影响未来 1-3 个月经营结构的问题。

```
🔴 结构高风险（需要进入战略调整）
  ├─ 收入过度集中（单一项目 >60%）
  ├─ 个人时间过度投入（>50% 用于维护）
  ├─ 多个项目长期停滞（>6 个月无进展）
  └─ 没有新产品在孵化

🟡 中等结构风险（建议观察并设定边界）
  ├─ 可复利收入 <20%（过度依赖服务/咨询）
  ├─ 新客户获取下降 (按月趋势)
  ├─ 单一技能栈依赖度 >70%
  └─ 技术债未清理

🟢 健康结构信号（继续保持）
  ├─ 至少 2 个项目在不同阶段
  ├─ 可复利收入 >30%
  ├─ 每季度至少 1 个新项目启动
  └─ 能力多样化（3+ 主要技能栈）
```

### 特性 3：战略动作建议

基于金字塔分析，为用户提供战略动作建议。建议语言应是经营结构层面的，不是任务列表层面的。

```
针对你的情况的战略建议

未来 30 天：
  1. 加码核心产品的商业化验证
     → 当前核心产品正在形成市场信誉
     → 但 Sell / Learn 信号不足，继续 Build 会降低复利效率
  
  2. 收缩低复利维护投入
     → 支持和重复修复正在挤占新收入源验证时间
     → 目标是释放稳定时间块，而不是新增项目

本季度：
  3. 建立第二收入源假设
     → 当前能力复利集中在 CLI / Agent 编排
     → 可测试教程、模板、服务产品化或 B2B 版本
  
  4. 降级或冻结长期停滞项目
     → 避免项目数量制造虚假的组合安全感
     → 组合价值来自复利关系，不来自项目数量
```

### 特性 4：场景建模与决策分析

支持"if-then"分析，帮助用户做长期规划决策：

```
如果我选择这个方向会怎样？

场景 A：深化 SoloMap（All-in 选项）
  ├─ 投入：从 45h/week → 60h/week
  ├─ 潜在回报：$50k-$100k/year（+200% 增长）
  ├─ 成本：其他 3 个项目停滞
  ├─ 风险：⭐⭐⭐ 单一产品过度依赖
  └─ 时间轴：12 个月

场景 B：建立产品组合（多头并进）
  ├─ 投入：45h/week 保持，优化分配
  ├─ 潜在回报：$35k-$45k/year（平衡增长）
  ├─ 优势：收入多元化、能力复用、风险分散
  ├─ 难点：每个项目的投入不足，增长缓
  └─ 时间轴：18 个月

场景 C：转向咨询/顾问（活跃收入）
  ├─ 投入：30h/week 产品，15h/week 咨询
  ├─ 潜在回报：$60k-$80k/year（高度数）
  ├─ 优势：收入立即增加，应用能力
  ├─ 风险：⭐⭐⭐ 咨询会挤占产品时间
  └─ 时间轴：6 个月

推荐路径：场景 B → 6 个月后评估是否切到场景 A
```

### 特性 5：不重复今日安排的动作边界

金字塔允许输出战略动作，但不输出今日任务队列。

| 可以出现 | 不应该出现 |
| --- | --- |
| 当前组合 Build 偏重，未来 30 天应减少新功能建设 | 今天先跑某个路线图环节 |
| 核心产品维护占用过高，应降低支持成本 | 现在去修某个具体 bug |
| 第二收入源缺失，应验证一个低成本商业化假设 | 今日安排第 1 项、第 2 项、第 3 项 |
| 某项目已从战略资产转为维护负担，建议冻结 | 点击这里继续当前任务 |

今日安排可以读取金字塔结论作为排序背景，但前台用户心智必须保持分离。

## 数据需求与技术集成

### 新增数据需求（分阶段最小化）

首版应尽量依赖 SoloMap 已有事实，避免把战略驾驶舱变成需要用户维护的配置系统。

战略驾驶舱的数据不能主要靠用户手填，也不能主要靠 Agent 猜。默认策略是：

```text
已有本地事实自动聚合
-> 少量稳定战略标记
-> 可选外部集成
-> Agent 低置信度解释与归纳
```

#### 1. 首版数据：已有事实优先

- 项目注册信息：项目类型、优先级、置顶/隐藏状态
- 路线图阶段：Build / Sell / Learn / Improve 分布
- 推进记录：最近路线图推进、最近 Solo 对话、长期停滞项目
- 交付信号：GitHub Actions / Release / Issue 反馈
- 跨项目学习：复用候选、执行速度、重复阻断和可复用模式

#### 2. 用户轻量标记：只收稳定战略信息

```json
{
  "projectStrategy": {
    "role": "core_product",
    "businessStage": "commercial_validation",
    "abilities": ["cli-tools", "agent-orchestration"],
    "strategicAction": "double_down"
  }
}
```

#### 3. 能力库维护（可选增强）

```json
{
  "abilities": [
    {
      "id": "cli-tools",
      "name": "CLI 工具设计",
      "marketDemand": "high",
      "projects": ["solomap", "cli-bench", "tool3"],
      "yearlyHoursBudget": 120,
      "yearlyRevenue": 8600
    }
  ]
}
```

#### 4. 收入数据（后续增强，与 Stripe/GitHub Sponsors API 集成）

```json
{
  "revenueStreams": [
    {
      "type": "saas",
      "project": "solomap",
      "monthlyRecurring": 2400,
      "automatability": 0.9
    },
    {
      "type": "template",
      "project": "template-react",
      "monthlyRecurring": 600,
      "automatability": 1.0
    }
  ]
}
```

### 数据来源优先级

1. **一级（可靠）**：SoloMap 已有本地事实和用户明确标记
2. **二级（推断）**：路线图阶段、推进历史、Issue / Release / Actions 信号
3. **三级（增强）**：Stripe、GitHub Sponsors、社区数据、品牌曝光等外部集成

任何推断都必须以“低置信度建议”呈现，不能伪装成财务或战略事实。

### Agent 的数据边界

Agent 只能做解释、归纳和建议，不能成为战略驾驶舱的事实源。

可以出现：

- “根据最近 3 个月推进记录，这个项目疑似维护负担偏高。”
- “该项目长期停在 Build，且缺少 Sell / Learn 信号。”
- “该能力在多个项目中反复出现，可能值得品牌化。”

不应该出现：

- “这个项目 ROI 低。”除非已有收入、时间投入和成本证据。
- “该项目已经 Product-Market Fit。”除非已有稳定付费、留存或高质量反馈证据。
- “品牌价值正在上升。”除非已有社区、媒体、引用、转化或渠道数据。

首版结论必须能追溯到证据。例如：

| 战略结论 | 证据来源 |
| --- | --- |
| 核心产品依赖度偏高 | 用户标记为核心产品 + 高时间负担 + 主要收入源 |
| Build 偏重，Sell / Learn 不足 | 多项目路线图阶段分布 + 近期反馈记录较少 |
| 某项目可能变成维护负担 | 长期无路线图推进 + 持续 Issue / Actions 修复记录 |
| 某能力正在形成复利 | 同一能力标签出现在多个活跃项目和执行记录中 |

数据采集原则：战略驾驶舱应该先读 SoloMap 已经知道的事实，只在必要处让用户补充少量稳定战略标签，不能把用户变成经营数据库维护员。

## 商业化与授权边界

战略金字塔适合作为 Pro 功能，但 SoloMap 的商业化不应改变 local-first 产品边界。

核心原则：

```text
SZLK Passport
- 用户是谁
- 是否订阅 SoloMap Pro
- entitlement / license 是否有效
- 设备或 seat 是否超限

SoloMap 本地
- 项目路线图
- Agent 运行记录
- 战略金字塔数据
- 经验库与学习候选
- Issue / Release / Actions 缓存
```

### Passport 的职责

SZLK Passport 只做身份、订阅和授权，不做 SoloMap 项目数据后端。

插件可以通过 Passport 完成：

- 登录 SZLK Passport
- 查询 `solomap_pro` 是否有效
- 缓存本地授权结果
- 支持订阅、续费、取消、试用、设备数或 seat 管理

插件不应该通过 Passport 上传或托管：

- 用户项目路线图
- Agent 对话与运行记录
- 战略金字塔判断数据
- 本地经验库、技能、连接器配置
- GitHub Issue / Release / Actions 缓存

### 授权体验

推荐流程：

1. 插件内显示“登录 SZLK Passport”。
2. 用户通过浏览器 OAuth 或 device code 完成登录。
3. 插件获得短期 token 或本地 license grant。
4. 插件查询 entitlement：`solomap_pro = active`。
5. 插件本地缓存授权结果，并提供 7-14 天离线宽限期。
6. 授权过期后降级到 Free，但不删除、不迁移、不锁死用户本地项目数据。

用户文案必须明确：

> 登录只用于验证 Pro 订阅，不上传你的项目路线图、Agent 记录或本地经验库。

### Pro 价值边界

Free 版解决单项目推进：

- 单项目路线图
- Agent Task Flow
- Solo 对话
- 基础侧边栏今日安排
- 本地数据与 Git 友好存储

Pro 版解决一人公司经营：

- 一人公司战略金字塔驾驶舱
- 跨项目战略信号
- 高级复用与学习分析
- 更完整的项目组合洞察
- 可选高级 Harness enhancement

商业化叙事：

> SoloMap Free 帮你推进一个项目。  
> SoloMap Pro 帮你把多个项目经营成一套一人公司系统。  
> 你的路线图、Agent 记录和项目数据仍然留在本地。

避免的方向：

- 不把 SZLK Passport 变成 SoloMap 数据后端。
- 不把每次打开 Pro 功能都做成实时授权请求。
- 不因为付费订阅而要求用户把本地项目数据同步到云端。
- 不把战略驾驶舱的数据来源从本地事实带偏成云端账号数据。

## 与 SoloMap 现有设计的集成

### 集成点 1：入口收口

项目级入口与组合级入口必须分开：

```text
项目卡片
└─ 打开项目大图 / Open Roadmap Graph
   进入：该项目的项目推进驾驶舱

侧边栏底部
└─ 战略金字塔 / Strategy Pyramid
   进入：一人公司战略驾驶舱
```

侧边栏底部不再保留单项目路线图大图按钮。项目路线图大图入口只在项目卡片上出现。

### 集成点 2：项目选择器交互

- 战略金字塔视图默认展示所有登记项目的经营结构。
- 点击金字塔中的项目，展示该项目的战略角色，而不是直接替代项目路线图。
- 如果用户要推进具体项目，应回到项目卡片或项目路线图大图。
- 金字塔内部可以提供“查看项目”跳转，但不能把单项目路线图入口重新做成底部第二个大按钮。

### 集成点 3：与 Agent 的联动

Agent 读取金字塔分析，在以下场景提供建议：

1. **路线图生成**（新项目）：
   > "从当前组合看，这个新项目应当复用你已有的 CLI / Agent 编排能力，并优先验证是否能补上第二收入源，而不是只增加新的 Build 项目。"

2. **路线图调整**（修改现有项目）：
   > "当前组合 Build 偏重，Sell / Learn 信号不足。这个项目的下一轮路线图应减少新功能建设，增加商业化验证与用户反馈吸收。"

3. **Solo 讨论**（临时问题）：
   > "从战略结构看，继续加码这个功能会提高核心产品依赖度。更稳的方向是先降低维护负担，再决定是否继续投入。"

4. **今日安排排序背景**：
   > "金字塔结论显示核心产品维护负担过高，因此今日安排可以把降低维护成本相关任务上提；但今日安排仍负责具体排序和入口。"

## 产品路线图与价值主张

### 版本 1.0（MVP，即时可实现）

**功能**：
- ✅ 一人公司战略驾驶舱入口
- ✅ 项目组合结构展示（Build/Sell/Learn/Improve 分布）
- ✅ 结构性风险信号（集中度、停滞、维护负担、反馈缺口）
- ✅ 单项目战略角色视图
- ✅ 战略动作建议（加码、收缩、暂停、转向、孵化）

**数据**：
- 优先使用现有项目注册、路线图、推进记录、Issue、Actions、Release、学习候选
- 支持少量用户战略标记，例如核心产品、孵化项目、维护项目、收入验证项目
- 不要求首版手动维护完整收入、能力 ROI 或品牌价值数据

**成本**：中等（主要是 UI、项目组合聚合和战略信号规则）

**功能**：
- 智能建议引擎（基于规则 + 简单启发式）

- 轻量收入结构分析

**数据**：
- 支持与 Stripe / GitHub Sponsors API 集成
- 从执行日志推断项目进展速度

**成本**：中~高（主要是推荐算法和规则库）

### 版本 3.0（高级，2027+）

**功能**：
- 自动时间序列分析（趋势预测）

- 退出价值分析（融资/收购/维护）

## 核心价值主张

### SoloMap 现有定位
> SoloMap 帮你把单个项目变成可推进、可验证、可交付的项目驾驶舱

### 金字塔升级后的定位
> SoloMap 帮你把多个项目、能力、收入、市场信誉和时间投入放进同一个一人公司战略驾驶舱

### 为什么这很重要

**独立开发者的真实问题不是**：
- ❌ "我今天先做什么"（侧边栏今日安排负责）
- ❌ "这个项目下一步怎么推进"（项目路线图大图负责）
- ❌ "哪个项目进度最慢"（简单 dashboard 可以做）

**独立开发者的真实问题是**：
- ✅ "我的项目组合是否正在形成可复利系统"
- ✅ "哪些项目是战略资产，哪些已经变成维护负担"
- ✅ "我的能力、收入、市场信誉是否互相增强"
- ✅ "我应该加码、收缩、暂停、转向，还是孵化新方向"

金字塔视图直接回答这些问题，而不是让用户自己拼凑数据。
