## 🔄 核心概念速查

### 六个项目类型

| 类型 | 特征 | 完成标准 | 初始路线图 |
|-----|------|--------|-----------|
| 核心产品 | 面向外部用户，需要获客和转化 | 完整的 Build→Sell→Learn→Improve 循环 | 5 个环节，完整四阶段 |
| 基础设施 | 为 3+ 个项目提供能力 | 被 2+ 项目正式接入，有版本管理 | 6 个环节，强调标准化 |
| 内容产品 | 周期性内容产出 | 按节奏完成 3 期内容，有工程化流程 | 6 个环节，强调生产流程 |
| 试验研究 | 验证想法或学习技术 | 学到了目标知识，记录到 .codex-memory | 4 个环节，允许失败 |
| 工具脚手架 | 提升自己或其他项目的效率 | 被 2+ 项目使用，有清晰文档 | 5 个环节，强调易用性 |
| 归档维护 | 已上线相对稳定的项目 | 系统稳定运行，监控告警完整 | 5 个环节，强调稳定性 |

### 优先级模型

```
P0 阻断    - 其他 3+ 个项目在等待这个完成
P1 核心    - 本周最该专注的方向
P2 积累    - 有空余时间就做，增强能力
P3 试验    - 利用碎片时间探索
```

### 全局学习流

```
单个项目学习  
    ↓
生成学习候选 
    ↓
周五审核（跨项目适用吗？）
    ↓ 是
提升到 .codex-memory
    ↓
下个项目自动查询
    ↓
能力复用，速度加快
```

## 📊 关键指标

| 指标 | 含义 | 如何跟踪 |
|------|------|---------|
| 环节完成速度 | 同类环节在不同项目中的耗时。目标：第三个项目比第一个快 70% | `.solomap-global/metrics/execution-speed-trends.csv` |
| 能力复用率 | 新环节所需能力中有多少是直接复用的。目标：从 0% 升到 85%+ | `.solomap-global/capability-registry.csv` |
| 跨项目决策冲突 | 提前发现冲突而不是事后爆发。目标：从被动到主动 | `.solomap-global/decision-conflicts.csv` |
| 学习提升成功率 | 周五审核的学习中，有多少最终被证实为真正跨项目适用 | `.solomap-global/metrics/` |

## 🛠 工具与基础设施

### 必需的文件和目录

```
.solomap-global/
├── portfolio.csv              # 所有项目的元数据和优先级
├── dependencies.csv           # 项目间的依赖关系
├── capability-registry.csv    # 能力复用情况跟踪
├── decision-conflicts.csv     # 决策冲突记录
├── .solopreneur-learning/     # 学习候选库（由 SoloMap 自动生成）
└── metrics/                   # 复利效果的度量数据
```

### 既有系统的角色

- **SoloMap** (`.solopreneur/`)：执行单个项目的方法论
- **`.codex-memory`**：存储跨项目的知识、决策、模式
- **`.solomap-global`**：协调全局优先级、依赖、能力复用

### 工作流集成

```
SoloMap 环节执行
    ↓
生成学习候选（`.solomap-global/.solopreneur-learning/`）
    ↓
周五人工审核（全局执行指南）
    ↓
提升到 .codex-memory（patterns/ / decisions/ / domains/）
    ↓
下个新项目初始化时自动查询
    ↓
复用已有方案，快速进行
```

## 常见问题

### Q：这套方法论适用于团队吗？

A：当前设计是为独立开发者（solo builder）优化的。但核心思想（复用能力、全局优先级、知识管理）对小团队也适用。团队使用时可能需要调整权力分配（例如优先级决策可能不再是单人）。

### Q：我该什么时候开始用这套方法论？

A：
- 如果你只有 1-2 个项目，暂时不需要
- 如果你有 3-5 个项目，开始使用 portfolio.csv 和项目分类
- 如果你有 5+ 个项目，全套方法论能显著提升效率

### Q：新增文档和既有的 SoloMap 方法论是什么关系？

A：
- SoloMap 方法论讲的是**单个项目从想法到规模化的循环**
- 全局方法论讲的是**多个项目如何协调和复用**
- 两者**不冲突，而是互补**。全局方法论把多个 SoloMap 循环编织成一个投资组合

### Q：我现有的 11 个已初始化项目需要迁移吗？

A：不需要马上迁移。你可以：
1. 先用 `portfolio.csv` 把他们分类
2. 新项目启动时用新的初始模板和流程
3. 既有项目继续按原方式运行，但启用"学习候选"生成
4. 逐步沉淀跨项目知识到 `.codex-memory` 和 `.solomap-global`

### Q：这套方法论能帮我快 3 倍吗？

A：取决于你有多少重复工作。根据分析，独立开发者的重复工作约占 30-50%。如果全部复用，理论上可以快 30-50%。实际会低于这个，因为每个项目也都有特殊之处。现实目标：第二个相似项目快 2 倍，第三个快 3 倍。

## 路径图（Roadmap）

### 阶段 1：基础积累（现在）
- ✅ 编写全局方法论文档
- ✅ 提供项目分类和模板
- ✅ 建立周期性操作流程
- ⏳ 建立 `.solomap-global/` 基础文件结构

### 阶段 2：有向复用（近期）
- ⏳ SoloMap 在初始化时自动查询 `.codex-memory` 推荐相似项目
- ⏳ Agent 在环节执行时自动引用全局 patterns 和 decisions
- ⏳ 自动生成学习候选，推送周五审核
- ⏳ 跨项目依赖关系可视化

### 阶段 3：自适应循环（长期）
- ⏳ 全局优先级自动计算（基于依赖、收入潜力、学习价值）
- ⏳ 项目间冲突自动检测
- ⏳ 复利指标自动跟踪和上升为操作建议
- ⏳ 多项目组合视图与仪表盘
