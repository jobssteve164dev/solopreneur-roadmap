# SoloMap 下一阶段功能优化开发文档

## 目标

把 SoloMap 方法论从文档变成产品里的默认推进系统。

SoloMap 下一阶段不应优先增加更多通用 Agent 能力，而应把用户带入一条清晰路径：

```text
发现问题 -> 打造产品 -> 卖给客户 -> 持续改进
```

对应到插件中的操作循环：

```text
项目想法 -> 方法论路线图 -> 下一步动作 -> Agent 对话 -> 本地交付 -> 状态闭环 -> 路线图更新
```

## 产品判断

当前 SoloMap 已经具备：

- 项目级 `.solopreneur/` 本地数据目录。
- Git 友好的 `roadmap.csv`。
- 路线图环节卡片。
- 环节内 Agent 对话历史。
- Agent CLI 指派、运行、停止、重试和文件修改记录。
- 路线图调整入口。

下一步的关键不是再增加一个入口，而是减少用户打开插件后的判断成本。用户应该立刻知道：

- 现在项目处于哪个阶段。
- 下一步最该做什么。
- 为什么是这一步。
- 可以直接让哪个 Agent 做。
- 做完后如何判断闭环。

## 优先级概览

| 优先级 | 功能方向 | 目标 |
| --- | --- | --- |
| P0 | 方法论路线图模板 | 让新项目路线图默认覆盖从问题到增长的完整路径 |
| P0 | Next Action 视图 | 用户打开插件后直接看到下一步动作 |
| P1 | 环节完成标准模板 | 让每个环节知道什么叫完成 |
| P1 | Build -> Sell -> Learn -> Improve 循环面板 | 把持续改进变成项目级循环 |
| P2 | 市场动作任务化 | 把品牌、官网、营销、销售、反馈变成 Agent 可执行任务 |

## P0：方法论路线图模板

### 用户价值

新项目不应只生成开发任务。健康的 SoloMap 路线图必须覆盖四层：

1. 问题与客户发现。
2. 产品基础与首个可用版本。
3. 分发、品牌、官网、营销和销售。
4. 反馈、数据、支持、单位经济模型和扩张。

这能避免用户把 SoloMap 当成普通 AI TODO 工具，也能让独立开发者从第一天就面向交付和市场。

### 产品行为

新项目初始化时，默认路线图仍保留“生成初始路线图”环节，但 Agent 被要求生成的真实路线图必须覆盖方法论四层。

路线图调整时，也应提示 Agent 不要只调整工程任务，而要检查是否影响：

- 问题定义。
- 产品交付。
- 市场触达。
- 学习与改进循环。

### 建议实现

新增一个方法论路线图指令文件，例如：

```text
.solopreneur/roadmap-methodology.md
```

内容由插件生成，写入项目 `.solopreneur/`，并在初始化路线图和路线图调整 prompt 中引用。不要把长方法论文本直接塞进 `roadmap.csv`。

模板要求：

- 至少包含四个阶段。
- 每个阶段至少有一个可执行环节。
- 每个环节必须有可交付结果。
- 不允许只生成“研究”“规划”这类无闭环任务。
- 市场阶段不能缺失。
- 学习改进阶段不能缺失。

### 验收标准

- 新项目生成的真实路线图覆盖四层方法论。
- `roadmap.csv` 中不出现大段提示词文本。
- 旧项目仍能正常读取现有路线图。
- 路线图调整后仍保留方法论覆盖，不会只剩工程任务。

## P0：Next Action 视图

### 用户价值

用户打开 SoloMap 时最需要的不是完整路线图，而是“我现在该做什么”。

Next Action 视图应成为侧边栏的核心入口，帮助用户直接推进，而不是先浏览所有卡片。

### 产品行为

侧边栏顶部新增一个紧凑区域：

```text
下一步
当前最该推进：{环节标题}
原因：{一句话}
输入框：补充这次要 Agent 做什么
Agent 选择器
发送按钮
```

它应直接复用环节对话链路，不创建新的任务系统。

### Next Action 选择规则

第一版可以用确定性规则，不需要额外 AI：

1. 如果存在 `Running` 环节，Next Action 指向该环节，提示用户查看运行状态。
2. 否则选择第一个 `Failed` 环节，提供重试入口。
3. 否则选择第一个 `In Progress` 环节。
4. 否则选择依赖已满足的第一个 `Pending` 环节。
5. 否则如果所有环节完成，指向路线图调整或 Build -> Sell -> Learn -> Improve 循环。

### 展示信息

Next Action 卡片应展示：

- 环节标题。
- 所属阶段。
- 当前状态。
- 最近一次 Agent 运行摘要。
- 修改文件数量。
- 主要失败原因或下一步建议。
- 直接发送 Agent 对话的输入框。

### UI 原则

- 不展示复杂解释。
- 不要求用户理解内部排序规则。
- 不引入新的“任务对象”。
- 只服务一个动作：继续推进当前最重要的环节。

### 验收标准

- 侧边栏打开后，用户能在首屏看到下一步动作。
- 点击发送后，走现有 `runAgent` 链路。
- 运行状态、失败、完成后，Next Action 会自动切换。
- 项目切换后，Next Action 与当前项目隔离。

## P1：环节完成标准模板（已落地）

### 用户价值

现在环节可以被用户点击完成，但“完成”标准还不够明确。每个环节应该有一个轻量闭环定义。

### 产品行为

每个路线图环节应拥有可读的完成标准：

- 本环节要交付什么。
- 完成后应该出现哪些文件、页面、配置或市场动作。
- 是否需要用户确认。
- 是否需要进入下一阶段。

### 建议数据结构

第一版不必改变 `roadmap.csv` schema。可以在 `.solopreneur/step-memory/<nodeId>.json` 中增加：

```json
{
  "completionCriteria": [
    "..."
  ],
  "lastCompletionEvidence": [
    "..."
  ]
}
```

如果未来需要在路线图中直接展示，再考虑扩展 CSV 字段。

### UI 行为

环节展开后，在对话输入区附近展示一段轻量完成标准。

不要做复杂表单。用户只需要：

- 查看标准。
- 让 Agent 按标准推进。
- 点击完成环节。

### 验收标准

- 新生成路线图的每个环节都有完成标准。
- Agent 对话 prompt 会要求 Agent 对照完成标准交付。
- 用户点击完成时能看到该环节标准。
- 旧项目无标准时不会报错。

### 落地说明

- 完成标准保存在 `.solopreneur/step-memory/<nodeId>.json` 的 `completionCriteria` 中，不改变 `roadmap.csv` schema。
- 旧项目打开时会按环节标题、阶段和 Agent prompt 自动补齐默认完成标准。
- Agent prompt 会读取并注入该环节完成标准；只有达到标准时才应写入完成判断。
- 大图中展开环节会展示完成标准；侧边栏环节卡片也提供“完成环节”按钮，用户点击完成前会看到同一份标准确认提示。

## P1：Build -> Sell -> Learn -> Improve 循环面板

### 用户价值

方法论里的规模化不是线性终点，而是循环。SoloMap 应帮助用户判断项目是否还在持续改进。

### 产品行为

在大图或侧边栏中增加项目级循环状态：

```text
Build：最近一次产品交付
Sell：最近一次分发/销售动作
Learn：最近一次反馈/数据输入
Improve：下一次改进任务
```

这个面板不应替代路线图，而是帮助用户看到项目是否只停留在开发阶段。

### 建议实现

第一版可以从路线图阶段和执行历史中推断：

- Build：最近完成的产品/工程阶段环节。
- Sell：最近完成的营销/销售/分发环节。
- Learn：最近完成的反馈/数据/支持环节。
- Improve：当前 Next Action 或最近一次路线图调整后的第一个可执行环节。

### 验收标准

- 项目至少显示四个循环槽位。
- 空槽位显示明确的下一步，而不是解释系统缺失数据。
- 点击槽位能定位到对应路线图环节。

## P2：市场动作任务化

### 用户价值

独立开发者最容易只写代码，不做分发。SoloMap 应主动把市场动作变成可交付任务。

### 建议任务模板

品牌：

- 定义产品一句话定位。
- 生成产品命名候选。
- 生成首版视觉和语气方向。

官网：

- 生成首页文案。
- 生成 FAQ。
- 生成安装或购买 CTA。

营销：

- 生成发布帖。
- 生成社区发布清单。
- 生成首批内容选题。

销售：

- 生成目标用户访谈问题。
- 生成冷启动私信。
- 生成首批潜在客户列表字段。

需求生成：

- 生成反馈收集表。
- 总结用户反馈。
- 把反馈转成路线图调整建议。

### 验收标准

- 方法论路线图中默认包含至少一个市场动作。
- 市场动作能像工程任务一样发起 Agent 对话。
- 市场动作的输出能落到项目文件中，例如 `docs/marketing/` 或项目自有文档路径。

## 推荐实施顺序

### 第一轮：P0 闭环

1. 方法论路线图模板。
2. Next Action 选择器和侧边栏入口。
3. 对应回归测试。

这一轮完成后，用户打开插件就能直接从方法论路线图进入下一步动作。

### 第二轮：完成标准

1. 为新路线图生成完成标准。
2. 在环节展开区展示。
3. Agent prompt 注入完成标准引用。
4. 用户完成按钮与标准关联。

### 第三轮：循环面板和市场任务

1. Build -> Sell -> Learn -> Improve 面板。
2. 市场动作模板。
3. 反馈转路线图调整。

## 非目标

下一阶段暂不优先做：

- 新 Agent CLI 大规模接入。
- 云同步。
- 账号系统。
- 团队协作。
- 复杂项目管理字段。
- 独立任务数据库。

原因：这些会增加系统复杂度，但不直接解决用户“下一步该做什么”的核心问题。

## 回归测试建议

新增测试应覆盖：

- 新项目 starter prompt 引用方法论模板。
- 生成路线图必须覆盖四个方法论阶段。
- Next Action 按状态优先级选择正确环节。
- 侧边栏渲染 Next Action 首屏入口。
- Next Action 发送任务复用现有 `runAgent` 链路。
- 项目切换后 Next Action 不泄漏上个项目状态。
- 文档或 README 改动不触发发布 workflow。

## 成功标准

下一阶段成功的标志不是功能入口更多，而是：

- 用户打开 SoloMap 后，首屏就知道下一步。
- 新项目路线图天然覆盖产品、市场和改进闭环。
- 每个 Agent 对话都绑定在路线图环节和完成标准上。
- Agent 交付后，用户能看到文件变化、状态变化和下一步变化。
- SoloMap 更像一人公司的操作系统，而不是 AI 聊天记录管理器。
