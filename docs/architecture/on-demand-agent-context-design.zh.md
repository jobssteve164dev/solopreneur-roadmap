# Agent 按需上下文架构设计

## 这份文档解决什么判断

这份文档固定 SoloMap 如何在不把记忆、技能、文档和运行账本全文塞进首次 Prompt 的前提下，让 Agent 可靠找到完成任务所需的上下文。

核心判断只有一句：**首次 Prompt 负责给出任务、硬边界和可执行索引；知识正文由 Agent 根据任务进展按需读取。**

## 适用范围

本文约束：

- Solo 首次对话的 Prompt 结构。
- `.solomap-global/memory/` 的发现入口。
- 项目文档 manifest、技能 registry 和执行经验账本的索引方式。
- Agent 查询历史经验时的正式工具契约。
- 用户全局要求如何避免全文重复注入。
- 后续 Step、Flow 和路线图调整迁移到按需上下文时应遵守的架构边界。

本文不定义：

- 具体记忆内容应如何撰写。
- 原始运行日志、SQLite 执行记录和 run digest 的存储格式。
- 某个 Agent CLI 自身的系统提示词或宿主级规则。

## 设计目标

- 用户当前任务始终是 Prompt 中最突出的内容。
- 不适用的技能、经验和文档不进入 Prompt，也不要求 Agent 再次判定跳过。
- 索引必须包含路径、用途和读取条件，而不只是文件列表。
- 历史知识可以为零；不得为了显得“有学习”而返回弱相关内容。
- 用户自定义全局要求不能因精简 Prompt 而丢失。
- 运行账本保留完整审计能力，但普通任务不直接消费原始记录。

## 架构分层

```text
用户当前任务
  -> 最小执行内核
  -> 按需上下文索引
       -> 项目规则与用户全局要求
       -> 分层记忆
       -> 项目文档 manifest
       -> 技能 registry
       -> 经验 retrieve 工具
  -> Agent 按任务读取正文
  -> 当前代码、日志和测试验证
  -> 结束前记忆分类
```

### 1. 最小执行内核

内核只保留当前运行无法依靠后续检索补回的边界：

- 当前运行类型和项目目录。
- 用户原始要求。
- 当前证据高于历史记忆。
- 不得擅自修改路线图和环节状态。
- 实现任务需要改动和验证，讨论任务直接给结论。
- 任务完成后的对话归属建议。

内核不得展开学习统计、候选数量、文档清单、历史 run、技能候选或跨 Agent 操作教程。

### 2. 按需上下文索引

每个索引项必须包含：

| 字段 | 作用 |
| --- | --- |
| 入口 | 文件、目录、manifest、registry 或可执行命令 |
| 用途 | 该知识解决什么判断 |
| 读取条件 | 什么任务或证据不足时才需要读取 |

Solo 首次索引至少覆盖：

- `agent.md`：项目执行规则。
- 用户全局要求文件：用户主动设置的跨任务约束。
- `profile.md`：用户长期偏好。
- `operating-rules.md`：跨任务执行规则。
- `projects/<project>.md`：当前项目稳定事实和入口。
- `decisions/`：已确认决策。
- `patterns/`：可复用实现、排障和验证模式。
- `domains/`：跨项目领域知识。
- `inbox/`：未经验证的临时观察，只能作为线索。
- `active/current-session.md`：当前会话交接。
- `.solopreneur/documentation.json`：项目正式文档目录。
- 技能 registry：技能发现入口。
- `solomap-experience.cjs retrieve`：高信号历史经验入口。

### 3. 用户全局要求索引

用户设置的全局要求属于必须可用的输入，不能因 Prompt 精简而消失。SoloMap 将其同步到全局上下文文件，首次 Prompt 只注入文件路径和优先级规则。

如果文件写入失败，不能伪装成已经索引成功；当前实现降级为不提供该路径，后续应通过可观测诊断暴露同步失败。

### 4. 经验检索契约

正式入口为：

```bash
node resources/tools/solomap-experience.cjs retrieve \
  --project "<project-root>" \
  --global "<solomap-global-root>" \
  --query "<具体功能、文件、错误或目标>" \
  --limit 5
```

检索同时消费：

- 全局学习候选。
- 当前项目 run digest。
- 当前项目 SQLite 执行记录。

输出分为两层：

1. 可复用经验：`判断 / 适用条件 / 应做 / 避免 / 置信度 / 证据`。
2. 证据入口：最多三条强相关 run，供 Agent 需要时继续追溯。

原始 `history`、`handoff` 和 `search` 继续存在，但只承担审计和接续，不是普通任务的默认知识入口。

## 相关性与质量边界

以下信息不得作为任务相关性的主要依据：

- URL、协议头和普通域名结构。
- 项目名、项目路径和运行类型。
- “完成、验证、修复、任务、对话”等流程高频词。

以下内容不得包装成经验：

- diff、源码片段和测试定义。
- Agent 的执行过程话术。
- 用量限制、终端关闭和完成套话。
- 只有文件名或命令输出、没有可复用判断的候选。
- 与当前查询类型不相符的验证模式或风险模式。

当没有内容达到门槛时，正确输出是空经验，而不是降低阈值凑满结果。

## 运行边界

- 首次 Prompt 不自动运行经验查询；普通首次任务通常不需要历史账本。
- 接续、复核、重复故障、历史行为调查或当前证据不足时才查询。
- 账本结果只是线索，不能覆盖当前代码、日志、测试和用户本轮证据。
- 不允许 Agent 直接遍历全部 learning candidates 绕过质量过滤。
- 项目文档只通过 manifest 发现，不在 Prompt 中展开全量目录。
- 技能只有确定使用后才读取 `SKILL.md`，不适用技能不进入 Prompt。

## 失败与降级

| 失败 | 正确降级 |
| --- | --- |
| 索引文件不存在 | 记录 skipped，继续当前任务 |
| 经验查询无结果 | 使用当前证据继续调查 |
| 经验查询只有低质量匹配 | 返回空经验，可给强相关 digest 入口 |
| 全局要求文件同步失败 | 不注入虚假路径，保留诊断能力 |
| 账本不可读 | 不阻断主任务，不用旧结论冒充当前事实 |

## 验证要求

按需上下文改动至少验证：

- 最终生成的 Solo Prompt 包含任务、内核、索引和读取条件。
- Prompt 不包含学习统计、账本正文、全量文档 Harness、不适用技能和历史交接正文。
- 用户全局要求文件实际生成且内容完整。
- 具体任务查询能返回结构化经验或强相关证据。
- URL-only 查询返回空结果。
- 真实项目账本不会把 diff、过程话术和完成套话重新包装为经验。
- Step、Flow 和路线图调整若未迁移，回归必须确认其既有入口没有被意外改变。

## 演进边界

后续把 Step、Flow 或路线图调整迁移到本架构时，应复用同一索引生成器和检索工具，不得复制第二套 Prompt 拼接逻辑。迁移必须按运行类型保留真正不同的硬边界，而不是重新引入全文注入。
