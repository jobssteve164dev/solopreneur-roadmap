## 3. 实施顺序与工作单位

默认顺序：**包1 → 包2 → 包3 → 包4 → 包5 → 包6 → 包7 → 包8。** 包1先稳定运行来源，包2建立全部结果消费者，包3完成真实学习闭环；之后关闭设置与后台、能力与资产、剩余分析，再完成数据带走及总验收。包4/5中已有成果保留，不因顺序改变重做。

任一时刻只推进一个完整包。一个包的工作单位是“用户动作从开始到结果、历史读取和恢复都成立”，修补函数、通过一个测试或关闭一个审查意见均不独立计为交付进度。

处理依赖时，只补当前包必需的合同，并把改动归入它真正所属的包；不因此把依赖包整体标完成，也不顺带展开其余功能。例如包1必须让安装入口拥有正式任务与运行身份，但安装登记、版本及卸载生命周期仍由包5验收。包1负责报告的运行归属和结果捕获，包2负责正式汇报提交、固定正文和全部读取者。交叉功能按同一证据引用验收，不重复制造夹具。

发现跨包缺口时，在原包编号登记，先完成当前包需要的部分。若当前包确实无法继续，记录具体缺失合同并转去完成该依赖；说明为何转移，不允许靠测试容易通过而换包。转移不得绕开已失败的验收或把它改成可选项。

## 4. 每包如何实施并一次验收

每包沿同一条链推进：**用户入口 → 正式生产写入 → 统一操作与身份 → 全部消费者 → 历史导入 → 并发/恢复 → 旧路径退出。** 不再先给所有包补大量底层代码，再长期逐个修测试。

1. 固定该包最终用户动作、真实入口和全部读写者。列出“入口/生产者、应用操作、消费者、历史来源、旧路径退出条件、验收位置”，必须绑定文件和函数；不以关键词搜索结果代替调用链核对。
2. 对缺口先做有效失败复现。夹具配置错误、模拟器缺字段等单独记录，不计作产品缺陷；修改实现只围绕真实缺口，不增加无关抽象或保护措施阻止结果完成。
3. 补齐该包整条链。历史导入显式只读，保留原始字节、hash、版本、项目归属、父子关系和旧别名；新任务不再产生对应永久业务文件。
4. 沿当前包所有入口和消费者做一组完整验收，覆盖本节下表。保留现有有效定向证据，只重跑代码变更实际影响的部分；整包最终候选必须有与该候选对应的新鲜验收。
5. 原台账中已有的重要审查发现先解决，最终对完整包做一次无实现历史的独立审查；若仍有重要问题，原项修复后复审，不把审查次数计进度。
6. 所有临时运行对象和测试夹具明确归类，关闭自有运行对象，按已授权生命周期处理本轮临时文件；正式证据保留。全部判据成立才把该包标“已验收（未发布）”。

## 6. 证据、磁盘与台账的最小维护

台账每包只留：状态、已经成立的结果、影响整包的缺口、下一验收、最终证据定位。当前状态仅使用“未闭环”“实施中”“已验收（未发布）”“已发布”；真实外部阻塞直接写原因，不增加假进度。单包被后续改动破坏时撤销验收并说明新证据。

每包用一份候选验收记录保存源码/生成物版本、有效命令结果、入口场景、历史对账、独审结论及实验处置。修复同一问题更新原记录；原始失败日志不覆盖。旧长账仅作历史索引，不再往主状态入口堆编译编号、哈希、清理数量和逐次审查叙事。

开始可能写入的验证前核对最终数据根、配置根、Runtime owner和执行器，不能仅依赖TMPDIR隔离。默认/自定义根都在同一隔离工作区内验证；不得改写共享HOME或真实CLI配置来制造测试条件。禁止停止生产或当前会话进程；真实生产恢复验收使用已有授权路径及可恢复边界，不用测试脚本强杀。

空间安排沿用户已要求的逐仓顺序，先只读定位大项与迁移状态，优先处理有明确归属、已不被消费的本轮夹具，不反复复制整库。不跨仓并发铺开迁移。存量空间不足时，列出具体待迁数据、可用空间和下一包需要的实际峰值，依据既有目标完成承接和对账；不能为腾空间删正文、证据或未经批准的历史。

本轮新建临时夹具先登记owner和精确边界，消费者结束后按授权生命周期处理；保留正式证据。非本轮新建文件不继承旧清理授权。禁止 `rm -rf`、批量删除和清空目录脚本；历史只生成逐文件清单，核验完整承接及所有引用退出后请求用户对该清单的明确授权。授权未到时保留历史原件，不阻断其他可独立完成的验收。
