# SoloMap 官网工作台本地优先架构设计

## 这份文档解决什么判断

这份文档固定 SoloMap 官网工作台与本地插件之间的职责、数据权威、同步协议、隐私边界和首版实现范围。

核心判断只有一句：**官网工作台是本地 SoloMap 的端到端加密遥控器，不是用户项目的云端副本。**

## 产品边界

SoloMap 由两个互补表面组成：

| 产品表面 | 用户用它完成什么 | 不承担什么 |
| --- | --- | --- |
| 本地插件 | 读取真实项目、运行 Agent、修改文件、验证结果、保存路线图与执行证据 | 不要求用户守在当前电脑前处理每个状态变化 |
| 官网工作台 | 跨设备查看推进状态、发起有限任务、补充要求、处理阻塞和确认 | 不保存项目副本，不直接运行 Agent，不成为第二份路线图权威 |

官网提交的是用户意图，本地插件掌握事实与执行权。官网点击“停止”只能产生停止请求；只有本地插件真正停止运行并回传结果后，界面才能显示“已停止”。

## 与协作生态的关系

官网工作台、私密协作房间和公共共创空间是三个不同的用户动作与信任边界，不能因为都经过官网就合并成同一套数据和权限模型。

| 能力 | 谁参与 | 解决什么问题 | 数据与权限边界 |
| --- | --- | --- | --- |
| 官网工作台 | 同一用户的浏览器与已授权本地设备 | 远程查看自己的项目状态并提交有限意图 | 设备配对、端到端加密、本地插件拥有执行权 |
| 私密协作房间 | 项目拥有者主动邀请的参与者 | Agent 工作期间交流、审计和提供反馈 | 独立房间密钥；默认临时；参与者不能控制 Agent |
| 公共共创空间 | 已登录用户 | 在 6 小时时段内进行可治理的项目互助 | 消息服务端可见并按时清空；不承诺端到端加密；不连接本地执行权 |

私密协作房间可以复用官网的 WebSocket 中继基础设施，但不能复用官网工作台的设备授权成为本地项目控制通道。官网工作台的“共创空间”标签只复用房间的邀请码、浏览器端加密和临时消息链路，不因此取得项目访问权。协作参与者发送的任何内容只能由项目拥有者主动选择为“带回自由研讨”或“快速新建笔记”，不得自动进入 Prompt、路线图、记忆或 Agent 执行。

公共共创空间不能用一个 `public/private` 开关从私密房间直接派生。公开内容需要独立的身份、限流、举报、删除和封禁机制。完整生态方向见 [SoloMap 独立开发者生态与协作网络战略](../product/solo-developer-ecosystem-strategy.zh.md)。

## 系统关系

```text
浏览器工作台
    <-> 端到端加密消息
SoloMap 同步中继
    <-> 只路由密文与连接状态
本地 SoloMap 插件
    <-> 本地项目、Agent CLI、路线图、日志与记忆
```

设备始终主动建立出站连接，不开放公网端口。中继服务不能直接访问本地文件、终端或 Agent CLI。

## 数据权威

### 本地插件是项目事实权威

以下数据只以本地为权威：

- 源代码和项目文件。
- `.solopreneur/` 中的路线图、运行记录和环节记忆。
- `.solomap-global/` 中的长期记忆和跨项目事实。
- 完整 Prompt、Agent 输出、终端日志、Git diff 和验证证据。
- Agent 运行是否真正开始、停止、完成或失败。
- 路线图环节和 Flow 的真实状态。

### 官网工作台是用户远程意图入口

官网工作台可以产生：

- 发起 Solo 请求。
- 补充正在进行的对话。
- 请求停止运行。
- 请求重试失败运行。
- 处理已有确认请求。
- 请求刷新当前状态投影。

官网不得直接覆盖本地项目状态，不得把命令已投递等同于命令已执行。

### 云端只承担连接与密文投递

服务端可以保存：

- 账户、套餐和设备数量等权益数据。
- 不含项目内容的设备标识、在线状态和最后心跳时间。
- 加密消息的消息 ID、顺序号、投递状态和过期时间。
- 服务端无法解密的短期密文。

服务端不得以明文保存：

- 项目名称、项目路径和项目列表。
- 路线图、下一步、任务标题和结果摘要。
- Prompt、Agent 输出、日志、文件名、Git diff 和代码。
- 用户确认事项的具体内容。
- 项目记忆、附件或环境信息。

## 本地化与端到端加密

### 设备身份

本地插件首次启用官网工作台时生成设备密钥对：

```text
devicePublicKey
devicePrivateKey
```

- 私钥只保存到 VS Code SecretStorage。
- 公钥可以注册到用户账户。
- 服务端不能获得设备私钥。
- 每台设备拥有独立身份，可以单独撤销。

### 浏览器授权

账户登录只证明用户身份，不自动授予项目内容解密权。新浏览器必须向已授权本地设备申请访问：

```text
浏览器登录
-> 生成浏览器会话密钥
-> 向指定设备申请授权
-> 本地插件展示浏览器与设备信息
-> 用户在本地确认
-> 建立工作台加密会话
```

浏览器密钥由 Web Crypto 生成并保存在当前浏览器的 IndexedDB。浏览器存储被清理后，应视为新浏览器并重新授权。服务端不托管可解密项目消息的恢复密钥。

### 密钥撤销与轮换

- 用户可以在插件中查看和撤销已授权浏览器。
- 撤销后必须轮换后续会话密钥。
- 旧浏览器不得继续读取新消息。
- 设备丢失时可以从账户侧撤销设备连接凭证，但账户侧不能恢复设备中的项目密钥或项目内容。

## 同步通道

### 在线主通道

在线状态使用 WebSocket 传输端到端加密消息，适合：

- 设备心跳。
- 运行状态变化。
- 待确认事项出现。
- 远程命令投递和执行回执。
- 浏览器请求当前状态投影。

WebSocket 只是传输方式，不是状态权威。连接中断不能导致命令重复执行或状态回退。

### 恢复与离线通道

HTTPS 用于：

- WebSocket 不可用时的命令拉取和事件补发。
- 断线重连后的游标恢复。
- 设备离线时的加密命令排队。

离线命令必须：

- 在浏览器端加密后进入中继。
- 设置明确有效期，首版默认七天。
- 由目标设备领取并在本地解密。
- 成功投递后删除消息正文，只保留不含项目内容的审计元数据。
- 到期后拒绝执行，不允许服务端自动续期。

设备离线时，官网必须显示“等待设备上线”，不能显示“正在执行”。

## 同步协议

### 消息信封

中继服务只识别不含项目语义的外层信封：

```json
{
  "messageId": "msg_...",
  "senderEndpointId": "endpoint_...",
  "recipientEndpointId": "endpoint_...",
  "sequence": 1042,
  "ciphertext": "...",
  "createdAt": "...",
  "expiresAt": "..."
}
```

项目 ID、运行 ID、命令类型和内容均位于密文内部。服务端不依赖项目语义完成路由。

### 允许的远程命令

首版命令必须使用固定白名单：

```text
solo.create
conversation.add_guidance
run.stop
run.retry
confirmation.resolve
projection.refresh
```

禁止提供 `run_shell`、任意命令字符串、文件读取或目录上传一类通用能力。本地插件根据命令类型构造既有产品动作，并再次执行权限、当前状态和风险检查。

### 命令生命周期

```text
queued
-> delivered
-> accepted / rejected
-> running
-> succeeded / failed / expired
```

- `delivered` 只表示设备收到密文。
- `accepted` 表示本地状态允许执行。
- 只有本地执行成功才能进入 `succeeded`。
- 浏览器不能根据超时自行推断成功或失败。

### 幂等、顺序和版本

- 每条命令有唯一 `commandId`，同一命令重复到达不得重复产生副作用。
- 每个端点维护单调递增的 `sequence`，断线后从最后确认位置继续。
- 改变运行状态的命令携带浏览器已知的本地状态版本。
- 本地版本已经变化时，插件拒绝旧命令并要求刷新。
- 插件使用本地持久化 outbox 保存未确认事件，插件重启后可以继续补发。

## 状态投影

官网不复制本地数据库，只请求本地插件生成当前会话所需的最小投影。投影在设备端生成、加密，在浏览器端解密和渲染。

首版允许展示：

- 用户选择展示的项目名称。
- 当前下一步的一句话描述。
- 运行状态与更新时间。
- 本地生成的有限结果摘要。
- 待确认数量和用户可执行动作。
- 当前执行设备是否在线。

首版禁止进入投影：

- 本地绝对路径和文件名列表。
- 代码、Git diff 和文件内容。
- 完整 Prompt、Agent 输出和终端日志。
- 环境变量、密钥、令牌和连接配置。
- 项目附件、长期记忆正文和数据库内容。

即使内容经过端到端加密，也必须遵守数据最小化；加密不能成为扩大同步范围的理由。

## 项目与设备关系

跨设备不能使用绝对路径识别项目。逻辑项目使用稳定的本地项目 ID，每台设备上的项目副本使用独立实例 ID：

```text
逻辑项目
├── 设备实例 A：当前执行设备
└── 设备实例 B：可见但不执行
```

首版每个项目只允许一个用户明确选择的当前执行设备：

- 不做自动机器调度。
- 有运行中任务时禁止切换执行设备。
- 非执行设备不得接受该项目的副作用命令。
- 项目 ID 和实例关系只在加密消息与本地存储中出现，服务端不建立可读项目目录。

## 日志与证据边界

官网首版只展示本地生成的安全摘要，例如：

```text
运行完成
验证通过 18 项
修改 3 个文件
等待用户决定是否调整路线图
```

完整日志、代码和 diff 只在本地插件中查看。官网对应动作应是“在 VS Code 中打开”，而不是把本地内容上传到网页。

后续如需临时查看更详细信息，必须另行设计用户明确授权、短时有效、点对点传输和脱敏机制；不得默认复用控制面同步通道上传完整内容。

## 用户确认与高风险动作

官网可以展示本地插件创建的确认请求，但首版只允许处理可安全远程确认的有限类型。

以下动作首版必须回到本地完成：

- 发布、部署和上架。
- 支付、账单和外部消息发送。
- 权限、凭证和外部账号连接。
- 删除或不可逆写入。
- 任意终端命令。
- 会直接影响生产用户的动作。

确认卡片必须说明本地生成的三个事实：Agent 已完成什么、为什么需要用户、确认后会发生什么。中继服务不能读取这些内容。

## 官网信息架构

### 今日

- 需要确认。
- 正在推进。
- 失败与阻塞。
- 最近完成。

### 项目

- 当前下一步。
- 当前运行。
- 最近结果摘要。
- 发起 Solo。

### 设备

- 在线状态。
- 当前执行设备。
- 浏览器授权和撤销。

### 账户

- Pro 权益。
- 设备管理。
- 隐私与同步设置。

现有 Early Access、权益和产品共创能力属于账户区域，不继续承担工作台主入口。

## 首版实现范围

首版闭环是：

```text
设备配对
-> 浏览器授权
-> 在线状态
-> 加密项目状态投影
-> 加密远程命令
-> 本地执行
-> 加密结果回执
-> 断线恢复与撤销
```

首版不做：

- 云端项目数据库。
- 文件上传、文件浏览和在线代码查看。
- 完整日志、Git diff 和 Prompt 同步。
- 在线路线图编辑。
- 多设备自动调度。
- 多人团队权限系统。
- 云端 Agent 执行。
- 任意远程终端。

## 验收标准

- 用户代码、路线图、记忆、Prompt、完整日志和执行证据不会进入同步请求。
- 服务端数据库不存在可读的项目内容字段。
- 捕获服务端网络和数据库内容时，只能看到连接元数据与密文。
- 新浏览器没有本地设备授权时无法解密项目投影。
- 撤销浏览器后，旧浏览器无法解密后续消息。
- 重复投递同一命令不会重复启动 Agent、停止任务或创建运行。
- 设备离线时命令显示为等待，不显示为执行中。
- 设备恢复后可以从最后确认序号继续同步，不丢失已完成结果。
- 状态冲突时以本地插件为准，官网刷新而不是覆盖本地状态。
- 完整日志、文件和 diff 只能从本地插件打开。

## 演进约束

后续扩展在线路线图、更多远程动作、点对点日志或多设备执行时，必须分别重新回答：

1. 用户正在完成什么动作。
2. 为什么该动作必须离开本地界面。
3. 是否可以只传输更小的状态投影。
4. 服务端是否仍然无法读取项目内容。
5. 本地事实权威是否保持唯一。
6. 断线、重复投递和旧状态是否会产生重复副作用。

任何扩展如果要求上传项目副本、把云端变成第二份状态权威，或让服务器能够读取项目内容，都不属于当前官网工作台边界。
