# SoloMap 自动化任务边界

## 这份文档固定什么

SoloMap 可以在任务运行结束或专注提醒到达时执行辅助动作。第一版产品名为 **自动化任务**，不对用户暴露 hook、event、adapter 或脚本概念。

核心判断只有一句：**自动化任务是用户授权的辅助动作层，不是主任务编排层。**

## 第一版范围

第一版只支持四类触发点：

- 任务完成后。
- 任务失败时。
- 手动停止时。
- 专注时间到。

第一版只支持内置动作：

- 系统通知。
- 播放声音。
- 番茄钟提醒。
- 重试任务。
- 使用自定义提示词自动发起新任务对话。

所有动作默认关闭，必须由用户在设置中勾选启用。

## 明确不做

第一版不开放自定义脚本、本地命令或 webhook。

第一版不做自动整理可复用线索。经验整理属于 SoloMap 学习管线和 Harness 自动化边界，不能作为这套轻量自动化任务的默认动作混入。

第一版不把番茄钟做成执行模式。番茄钟只是提醒机制，不改变 Agent 运行、暂停、恢复或任务状态。

第一版不在前台展示自动化执行记录。底层可以保留记录，用于后续排障和展示。

## 主任务边界

自动化任务不得阻断主任务：

- 不阻断任务状态写回。
- 不影响路线图、Solo、侧边栏或运行历史刷新。
- 不改变原始任务的完成、失败或停止结果。
- 自动化失败只能记录为自动化失败，不能反向污染主任务。

重试任务和自动发起新任务对话都必须复用现有对话发起链路，不能另造一套 Agent 启动逻辑。

## 自动发起新任务对话

用户可以为触发点配置自定义提示词。触发后 SoloMap 自动发起一条普通任务对话，而不是只预填输入框。

这类自动循环与 Flow 不同：

- Flow 是目标驱动的多步自动编排。
- 自动化任务只是用户在某个触发点后授权发起一次普通对话。

为了避免无限循环，第一版应对同一原始对话做轻量防重。自动重试或自动接续失败时，不应无限再次触发同类自动化。

## 设置页呈现

配置入口放在设置中，参考现有能力扩展组件的紧凑形态。

UI 原则：

- 尽量压进下拉框或折叠区。
- 不占用设置页大量空间。
- 默认只显示当前触发点和已启用动作摘要。
- 展开后再配置系统通知、声音、重试和自定义提示词。

前台文案只描述用户动作和结果，不描述 hook、payload、adapter、事件名或内部记录结构。
