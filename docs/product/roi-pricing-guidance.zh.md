# SoloMap Pro ROI 分析与定价指导报告

**日期**: 2026-06-03  
**适用范围**: SoloMap Pro、金字塔战略驾驶舱、后续 SZLK Passport 订阅授权设计  
**报告性质**: 长期定价基准，不是一次性促销方案  

---

## 1. 结论

SoloMap Pro 的定价不应按服务器成本定价，也不应按 AI 编码工具的价格直接锚定。它应该按用户获得的经营 ROI 定价：

> Free 帮用户推进一个项目；Pro 帮用户经营一人公司。

首版建议价格：

| 阶段 | 建议价格 | 目的 |
| --- | --- | --- |
| Early Access | **$29/年** | 验证真实付费意愿，降低早期门槛 |
| 正式首发 | **$5/月 或 $49/年** | 保持低摩擦，同时不把产品降格为玩具 |
| 成熟后 | **$9/月 或 $79/年** | 当金字塔判断模型、反馈闭环和战略建议成熟后提价 |

不建议低于：

- **$3/月**
- **$19/年**
- 低价终身授权

原因：SoloMap 当前边际服务成本低，但未来主要成本会来自支持、兼容、订阅系统维护、产品判断模型打磨和商业化运营。过低价格会制造错误信号：用户把它当成小工具，而不是一人公司的战略驾驶舱。

---

## 2. 产品价值边界

金字塔战略驾驶舱不是一个可视化组件，也不是第二个今日安排。它的付费价值来自更高层的判断：

- 哪些项目值得继续投入。
- 哪些项目只是在消耗维护时间。
- 当前是否过度 Build、缺少 Sell / Learn。
- 哪些能力正在形成跨项目复利。
- 市场信誉、收入结构和交付能力是否互相增强。
- 一人公司的时间、项目、能力、收入是否构成可持续系统。

因此，Pro 价格不应解释为“买一个金字塔图”。正确解释是：

> 购买一个本地优先的一人公司战略判断层。

---

## 3. ROI 模型

SoloMap Pro 的用户 ROI 应按三项计算：

```text
用户月 ROI = 节省时间价值 + 避免错误决策价值 + 提高交付概率价值 - 订阅价格
```

### 3.1 节省时间价值

```text
节省时间价值 = 每月节省小时数 × 用户每小时机会成本
```

保守模型：

| 项目 | 保守估算 |
| --- | --- |
| 每周少纠结下一步 | 0.5 小时 |
| 每周少整理项目状态 | 0.5 小时 |
| 每月节省时间 | 4 小时 |
| 独立开发者机会成本 | $15-$30/小时 |
| 月节省价值 | $60-$120 |

在这个模型下，$5/月或$49/年的价格很容易成立。

### 3.2 避免错误决策价值

```text
避免错误决策价值 = 避免浪费小时数 × 用户每小时机会成本
```

金字塔视图最值钱的部分不是告诉用户“今天做什么”，而是发现结构性错误：

- 多个项目同时 Build，缺少市场验证。
- 一个项目持续推进，但没有反馈、收入或分发信号。
- 高维护项目吃掉了新产品验证时间。
- 技术能力投入没有形成可复用资产。
- 用户把时间花在低回报项目上。

保守模型：

| 项目 | 保守估算 |
| --- | --- |
| 每月避免一次错误投入 | 3 小时 |
| 独立开发者机会成本 | $20/小时 |
| 月避免损失 | $60 |

只要金字塔视图每月帮用户避免一次低价值投入，Pro 价格就有充分 ROI。

### 3.3 提高交付概率价值

```text
交付概率价值 = 项目潜在收益 × 完成概率提升
```

示例：

```text
项目潜在收益 = $1,000
原完成概率 = 20%
使用 SoloMap 后完成概率 = 30%
期望收益提升 = $1,000 × (30% - 20%) = $100
```

这项价值真实存在，但不适合早期直接写进营销文案，因为它依赖用户项目质量、市场需求和执行能力。它更适合作为内部定价判断。

---

## 4. 用户分层与可支付能力

SoloMap 的早期用户不是企业采购，也不是纯消费者。他们更像“为自己的一人公司购买生产力工具”的独立开发者。

| 用户类型 | 支付心理 | 合理价格 |
| --- | --- | --- |
| 试用者 | 还没形成项目工作流，只愿意免费试 | Free |
| 轻量独立开发者 | 有 1-2 个项目，希望少丢上下文 | $29/年早鸟 |
| 多项目独立开发者 | 同时推进多个产品，需要战略取舍 | $49-$79/年 |
| 高频 Agent 用户 | 已经把 Agent 当日常生产力，需要跨项目经营层 | $9/月或更高 |
| 小团队/代理商 | 需要共享状态、报告和客户项目治理 | 后续 Studio/Team |

第一阶段不建议做复杂分层。只需要：

- Free
- Pro

原因：当前最重要的是验证“金字塔战略驾驶舱是否能让用户付费”，不是优化套餐结构。

---

## 5. 成本模型

SoloMap 当前边际成本低，因为核心逻辑是本地优先：

- 项目数据保存在用户本地。
- Agent 执行依赖用户已有本地 CLI。
- 金字塔视图首版使用本地事实、用户标记和本地聚合。
- SZLK Passport 只做订阅授权，不承载项目数据。

但后期成本会集中在以下位置。

### 5.1 支持成本

这是早中期最大隐性成本。

可能来源：

- VS Code、Cursor、code-server、VSCodium 等宿主差异。
- 不同 Agent CLI 的参数、权限和会话行为变化。
- GitHub CLI 授权、远程仓库、Actions、Release 数据差异。
- 用户本地路径、权限、shell、PATH 和文件损坏。
- Open VSX 与 VS Marketplace 分发差异。

定价含义：

> 低价可以，但不能低到无法覆盖支持时间。

### 5.2 订阅与授权成本

如果挂到 SZLK Passport，成本包括：

- 支付手续费。
- 订阅状态校验。
- 授权失败排查。
- 退款、续费、换设备、账号安全。
- 隐私与合规说明。

这不是高金额成本，但会带来持续维护责任。

### 5.3 产品判断模型成本

金字塔战略驾驶舱的核心成本不是 UI，而是判断模型：

- 如何判断项目该加码、暂停、收缩或转向。
- 如何判断 Build / Sell / Learn / Improve 失衡。
- 如何把本地事实转为可信战略建议。
- 如何避免过度自信或错误建议。
- 如何让用户相信“这个视图懂我的一人公司”。

这部分是 SoloMap Pro 的长期护城河，也是后续提价依据。

### 5.4 云端 AI 成本

只要坚持本地优先，云端 AI 成本可以接近于零。

成本会明显上升的情况：

- 托管 Agent run。
- 云端战略诊断。
- 多设备同步。
- 云端项目分析。
- 自动周报/月报由云端模型生成。
- 远程记忆库或团队协作空间。

定价含义：

> 当前 Pro 可以低价；一旦进入托管 AI 服务，就必须重新设计 usage-based 或更高套餐。

## 6. 市场锚点

SoloMap 不应与主力 AI 编码工具抢同一笔预算。它应作为这些工具之上的项目生命周期控制面。

当前外部价格锚点：

| 工具 | 价格锚点 | 含义 |
| --- | --- | --- |
| GitHub Copilot Pro | $10/月 | 个人 AI 编码工具低位锚点 |
| GitHub Copilot Pro+ | $39/月 | 高频 AI 能力和高级模型锚点 |
| Cursor Pro | $20/月，年付折 $16/月 | AI IDE 主力个人付费锚点 |
| Cursor Pro+ | $60/月，年付折 $48/月 | 高频 Agent 用户锚点 |

SoloMap 的早期价格应明显低于 Cursor Pro，也不应高于 Copilot Pro。合理策略是：

```text
SoloMap Pro < Copilot Pro 月付价格 <= 主流 AI IDE 月付价格
```

因此，$5/月和$49/年是当前最稳妥的正式首发价格。

## 7. 免费版与 Pro 版边界

### Free 应该保留

- 单项目路线图大图。
- 今日安排。
- 本地 Agent 推进。
- 基础执行历史。
- 基础反馈 Issue。
- 本地优先项目数据。

Free 的任务是让用户形成习惯：

> 以后推进项目先打开 SoloMap，而不是重新打开一堆聊天和 TODO。

### Pro 应该解锁

- 金字塔战略驾驶舱。
- 多项目战略评分。
- 项目组合健康度。
- 能力复利分析。
- 市场、收入、交付结构诊断。
- 战略视图影响今日安排排序背景。
- 更完整的反馈统计摘要。
- 后续 SZLK Passport 订阅授权。

Pro 的任务是让用户形成经营心智：

> 我不是在管理任务，而是在经营一人公司。

## 8. 付费触发点

付费提示不应出现在安装后、首次打开后或用户尚未体验价值前。

建议触发：

1. 用户登记了 2 个以上项目，并点击金字塔入口。
2. 用户完成过至少 1 次路线图 Agent 推进，并点击金字塔入口。
3. 用户本地统计显示多次 Solo / Agent 对话后，系统发现项目组合层面的结构风险。
4. 用户试图查看多项目战略评分或能力复利分析。

建议文案方向：

> 你已经在 SoloMap 里推进了多个项目。金字塔战略视图可以帮你判断：哪些项目该继续，哪些该收缩，哪些能力正在形成复利。

必须保留清晰退出：

- “稍后再说”
- “继续使用 Free”
- “查看 Free 可以做什么”

不要使用羞辱、焦虑、倒计时或隐藏关闭按钮。

## 9. 价格实验

早期最重要的不是 ARPU 最大化，而是验证真实商业信号。

### 9.1 第一阶段：验证愿意付费

建议：

- 价格：$29/年 Early Access。
- 目标：验证真实用户是否愿意为 SoloMap 付费。
- 判断：有人付费，比免费安装量更重要。

成功信号：

- 10 个以上真实付费用户。
- 付费用户中至少 30% 主动打开金字塔视图。
- 至少 5 个用户通过反馈 Issue 或访谈表达“项目取舍/多项目经营”价值。

### 9.2 第二阶段：验证正式价格

建议：

- 价格：$5/月 或 $49/年。
- 目标：验证低摩擦订阅是否成立。

成功信号：

- 年付占比高于月付，说明用户相信长期价值。
- 退款原因不是“太贵”，而是功能成熟度问题。
- 金字塔视图成为 Pro 用户的主要入口之一。

### 9.3 第三阶段：成熟后提价

条件：

- 金字塔判断模型稳定。
- 用户能看到明确结构性建议。
- 战略视图能影响今日安排排序。
- 反馈统计能证明 Pro 用户更常完成路线图环节或发布。

建议价格：

- $9/月
- $79/年

## 10. 决策规则

后续所有付费模型讨论应遵守以下规则。

### 规则一：不按成本定价

成本低只能说明毛利空间大，不能说明价格应该极低。定价应绑定用户 ROI。

### 规则二：低门槛，不低尊严

SoloMap 可以比 AI IDE 便宜，但不能便宜到用户认为它不是严肃工具。

### 规则三：先年付验证，再复杂分层

早期 $29/年比 $3/月更适合验证。年付更能证明用户相信长期价值，也减少订阅流失噪音。

### 规则四：不要过早卖终身

终身授权会损害未来支持成本、订阅系统和产品判断模型迭代空间。只有在明确限量、明确早期访问属性、并且不包含未来高成本云端能力时，才可考虑。

### 规则五：云端 AI 另算

只要未来引入托管 Agent、云端 AI 分析或多设备同步，就必须把它从当前本地优先 Pro 定价中拆出来，避免低价套餐吞掉高成本服务。

---

## 11. 后续设计基准

后续设计付费模型时，以以下基准为准：

1. 首版 Pro 的核心付费理由是金字塔战略驾驶舱。
2. 首版正式价格基准是 $5/月或$49/年。
3. Early Access 基准是 $29/年。
4. Free 必须保留项目推进闭环，不能把核心使用路径切坏。
5. Pro 不能只是“更多数量限制”，必须提供经营层判断。
6. SZLK Passport 只承载订阅授权，不承载用户项目数据。
7. 如果未来成本结构从本地软件授权变成云端 AI 服务，必须重新定价。
