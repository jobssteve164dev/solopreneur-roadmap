# 生长图工作汇报与学习管道验收

## 范围

本批实现现有生长图内的工作汇报台账、模块与能力双向联动、验证来源和版本判断，以及查看、定位、原任务继续处理、用户主动更新验证结果。没有重排首屏、扩展协作矩阵、增加历史比较或改变路线图完成标准。

实现入口：`growthReports.ts`、`growthReportsWebview.ts`、`projectGrowth.ts`、`projectGrowthWebview.ts`。报告仍由原 checkpoint 保存，GitHub 采集仍复用 `learningReview.ts`，语义复盘仍走原设置入口。

## 自动回归

| 场景 | 验证范围 |
| --- | --- |
| 稳定任务、旧格式与非代码任务 | 不同 CLI 的同任务登记；字符串/对象数组、未知字段、无提交、缺失字段及未完成筛选 |
| 轮次与修订 | 新轮不覆盖旧轮；同轮 A→B→A 保留次序；共享运行目录按宿主执行身份归属；半写入不产生重复轮次 |
| 来源和关联 | 跨项目、软链接及伪造执行身份拒绝；明确文件范围关联模块与能力；模块重划保留未知；共享提交按各任务范围处理 |
| 证据与失败 | 报告声明独立于失败检查；分页中断可恢复；局部失败保留旧检查及原时间；大于 1 MiB 的累积证据不消失 |
| 验证时效 | 同大小源码修改使旧覆盖过期；重新打开缓存视图也核对源码版本；静态 100% 引用不生成已成形结论 |
| 并发与显示 | 同范围远端请求合并；来源变动后重读；迟到快照写入不覆盖报告投影；任务分页与按需轮次读取 |
| 原会话续聊 | 保留路线图状态、登记实际新执行、复用恢复后的活跃终端、排除无关任务；Codex 明确粘贴后提交 |
| 手动复盘 | 生成与独立复核分离；精确补丁和旧版本拒绝；中断沿同 runId 恢复且不覆盖旧材料；合理未决项允许零改动应用 |

相关测试：`growth-reports.test.js`、`learning-review.test.js`、`project-growth.test.js`、`project-coverage.test.js`、`terminal-compatibility.test.js` 和 `webview-regression.test.js`。

## 真实插件与 CLI

使用隔离 code-server 宿主、独立项目登记与全局数据目录，通过真实 SoloMap 按钮启动 Codex 0.153.4。没有把 fixture 报告冒充 Agent 实际产出。

- 新 Solo 最终启动提示词包含结构化汇报和 `SoloMap-Task` 提交规范；实际生成脚本经语法检查并由终端执行。
- 同一真实任务保存四份报告，覆盖首轮、活跃会话续聊、重启后的原生会话恢复及恢复后的再次续聊。最后一次按钮操作直接送达活跃 Codex，无需额外按终端回车；新执行沿同一任务登记，在原运行目录保存新轮报告。
- 实际产出包括阅读计划和 `src/reading.js`，Node 实际调用函数并断言返回两条计划。报告中的产物摘要可与磁盘文件核对。真实生长图显示报告、定位源码模块，并经已有编辑器打开产出。
- 先前验收中误发起的一次并行恢复失败已保留为失败材料；它暴露的活跃终端查找缺口已修正并重新通过真实按钮验收，没有将该次失败计入成功轮次。
- 原设置发起的一次手动复盘在中断后沿同一 runId 恢复。独立复核通过，应用状态 `applied`、无错误；结果为无指令、记忆或经验变更，18 个隔离材料文件哈希保持不变。原任务未证实的边界保留未决，复核通过不代表原任务全面验收。

隔离任务明确不提交、不推送。当前项目的真实提交 trailer、报告仓库/完整 SHA/文件范围、GitHub 精确 diff/checks 及无主动报告时的独立发现，单独记录在本次任务的最终汇报与 GitHub 回读材料中；不得用隔离结果替代这一项。

## 真实界面及最终生成物

发布包代码在真实宿主加载；最终 HTML 的内联脚本通过解析，包内编译模块与受测编译结果逐个比对。VSIX 打包审计通过。验收宿主使用独立入口包装器记录命令名，未改变被测业务模块。

双项目同编号运行场景使用明确标注的隔离 fixture，真实界面操作覆盖模块/能力筛选、反向定位并展开详情、清除筛选、展开报告、刷新及项目切换后恢复状态。A 的报告不会覆盖 B；无模块任务仍能在全部汇报阅读。半写入时保留旧正文，恢复后没有重复轮次；无远端仓库时刷新验证结果失败，原报告可读且按钮可重试。

普通打开、刷新和项目切换的宿主命令审计没有发现新增模型、GitHub 拉取或测试调用，任务运行目录和复盘运行数不变。此前普通用户视角二次检查的通过结论已被用户实际反馈推翻：整段指令当标题、过程字段平铺、相邻卡片零间距和窄屏遮挡均未满足直接使用标准，按体验流程事故处理。

## 工作汇报纠偏验收

本轮以简短成果、实际价值及需要介入的事项为汇报目的，同时约束生成和留档字符数，避免把降噪责任留给读者或后续经验复盘。原报告、任务身份、续聊与查看入口保留。

- 当前项目真实长任务和报告用于浏览器复现；修改前在 320/390/600/900/1440px 测得汇报上下间距均为 0，多处模块名称和状态越界。相同检查修改后通过，最终生成脚本可解析且初始化执行。
- 可复用浏览器回归：编译后运行 `NODE_PATH=/usr/local/lib/node_modules node test/browser/growth-reports.cjs`（需可解析的 Playwright 包与 Chromium；`CHROMIUM_PATH` 可指定浏览器）。测试创建独立项目，覆盖长要求、长留档、多轮记录、模块换行、间距、按需查看和继续原轮次；所有宿主动作在触发前被测试桥接拦截，不发起真实续聊、GitHub 请求或测试执行。截图与结果保存在输出的独立目录，正式保留为验收材料。
- 字符预算回归使用最终 checkpoint 脚本，验证超限拒收、原稿不截断、任务仍可结算、Unicode 字符、精确边界及证据字段不能夹带正文；旧格式和旧超长报告仍进入全局复盘来源并可在生长图查看，不能用新预算删除历史证据。
- 浏览器回归使用旧版超长 summary：默认层只显示不超过 120 字符的结果预览，首次打开的最新任务直接呈现待处理事项与继续动作，完整旧 summary 仍可从“产出与依据”读取。
- 全局复盘路径回归同时写入无 `projectPath` 的 schemaVersion 2 语义处置记录，确认其进入 `candidate-decisions` 来源清单，而不是只有提示词列出目录。
- 此轮不重跑已完成的真实 CLI/手动复盘演练；前文证据仍只代表原轮范围。新字符限制由生成指令和实际接收、复盘读取路径共同验证，不以模型必然遵守指令为前提。
- 本轮专项测试覆盖报告展示、字符预算、全局复盘输入路径与提示词；完整测试的唯一已知失败仍为上文已核对的会话 pointer 场景。最终独立审查对当前完整差异未发现 Critical、Important 或 Minor；执行者与精确时间保留在按需查看的依据中。第二遍检查使用真实长报告和独立长内容项目，检查结果主次、窄屏阅读及动作可达性。

1000 个实际落盘任务的本地实验：首次建立报告索引约 1.23 秒，其间事件循环持续响应；下一页约 0.91 秒，仅读取数据库，不重读报告正文，每页返回 20 项。该结果是本机观察，不是所有机器上的延迟保证。

## 材料与边界

真实 CLI 证据只覆盖 Codex。其他 CLI 的任务归组、报告兼容及终端既有行为由自动测试覆盖，本轮未逐一运行其真实二进制。发布与检查结果以任务最终报告中的精确提交和既有 CI/扩展发布回读为准，不以 CI 或覆盖率代替用户目标验收。
