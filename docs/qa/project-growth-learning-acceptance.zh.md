# 生长图工作汇报与学习管道验收

## 2026-09-18 经验复盘职责边界纠偏

经验复盘的验收主结果不是 manifest、候选数或复核 verdict，而是设置中的全局默认提示词已被本轮 Agent 生成的完整版本替换并回读一致。即使有证据缺口，也必须生成并应用其余有效结论；没有高价值新增时允许应用语义不变版本，不允许返回空提案。

质量与接续必须同时验证：结果中的每项新增、合并、修订和删除都带精确前后文本、已处理的正式正文来源与理由，删除另带受限依据类型，以及覆盖或同义删除时最终版本中保留文本的定位；提示词、索引、删除墓碑与旧候选不得给任何变化自证。任务和报告必须通过登记任务、execution 与报告 envelope 身份校验，孤立或伪造报告不得成为来源；active 索引中先缺失后出现的文档必须在索引未变化时仍被发现；已处理来源的游标也要保存可验证正文，以便删除墓碑继续携带原始证据；Agent 登记的精确提交只在退出后按实际引用项定向核验。任何没有记录的旧约束消失、新约束、首尾空白、Markdown 缩进或内部空行变化、用相同文本伪造修订来隐藏重排、遗漏正式来源都应拒绝；空提示词且零来源时仍能形成首版。连续两轮使用相同材料时，第二轮不得再读取或提交已应用且内容未变的正文；只允许枚举文件身份与检查元数据，新增、变化和延期来源继续进入。延期来源必须保存原文版本快照；若延期期间再次修改，`previousVersions` 必须保留所有尚未处理的旧版本，删除后仍保留旧正文并可继续延期。只有提示词成功写入并回读后才推进游标；尚未写入成功的旧完整提示词只能承接，旧 `applying/partial` 结果必须逐一落成终态，失败结果不得吞掉证据。

既有“立即显示终端”“一次点击只启动一个 Agent”和真实复盘产物验收，没有覆盖点击到 Agent 进程实际启动之间的顺序。此前版本会先由插件宿主全量收集登记项目材料与 GitHub 事实，再发送 Agent 命令；该行为已被用户否定，原验收不得继续作为入口响应或职责边界通过证据。

纠偏实现的必测场景固定为：项目枚举与证据校验不得在 Agent 启动前发生；启动前也不能借完整设置读取触发增强探测、技能初始化或共享写入；真实子进程先写入启动标记，插件随后才能读取项目范围。Agent 自行读取增量索引、采集材料、按需查询证据并承接旧应用成果；插件只在结果阶段核对 Agent 实际引用的正式来源、输入版本、完整提示词、变更账本和游标更新，不重建全量材料，也不要求独立子智能体复核包。范围必须与 Agent 可见输入一致：排除 hiddenProjects；缺少 projects.json 时只用当前工作区，不注入只存在于插件 globalState 的旧项目。复盘沿用普通 Agent 任务的 CLI 权限模式，不得发明阻断跨项目读取或任务完成的专用权限契约。自动回归覆盖真实进程启动、启动前零业务动作、只读结果核验、锁竞争与恢复；发布包验收仍需从按钮观察实际 Agent CLI。

共享项目根目录 `/home/ubuntu/project/agent.md` 是上述项目范围规则的明确例外：即使 `/home/ubuntu/project` 位于 `hiddenProjects`，该单一文件仍必须作为 `global_constraint` 进入 Agent 启动后的增量证据链。正文变化后必须重新进入；只有正文未变时才能仅刷新版本游标而不重复语义复盘。

## 范围

本批实现现有生长图内的工作汇报台账、模块与能力双向联动、验证来源和版本判断，以及查看、定位、原任务继续处理、用户主动更新验证结果。没有重排首屏、扩展协作矩阵、增加历史比较或改变路线图完成标准。

实现入口：`growthReports.ts`、`growthReportsWebview.ts`、`projectGrowth.ts`、`projectGrowthWebview.ts`。报告仍由原 checkpoint 保存，GitHub 采集仍复用 `learningReview.ts`，语义复盘仍走原设置入口。

发布包代码在真实宿主加载；最终 HTML 的内联脚本通过解析，包内编译模块与受测编译结果逐个比对。VSIX 打包审计通过。验收宿主使用独立入口包装器记录命令名，未改变被测业务模块。

## 工作汇报纠偏验收

本轮以简短成果、实际价值及需要介入的事项为汇报目的，同时约束生成和留档字符数，避免把降噪责任留给读者或后续经验复盘。原报告、任务身份、续聊与查看入口保留。

- 当前项目真实长任务和报告用于浏览器复现；修改前在 320/390/600/900/1440px 测得汇报上下间距均为 0，多处模块名称和状态越界。相同检查修改后通过，最终生成脚本可解析且初始化执行。
- 可复用浏览器回归：编译后运行 `NODE_PATH=/usr/local/lib/node_modules node test/browser/growth-reports.cjs`（需可解析的 Playwright 包与 Chromium；`CHROMIUM_PATH` 可指定浏览器）。测试创建独立项目，覆盖长要求、长留档、多轮记录、模块换行、间距、按需查看和继续原轮次；所有宿主动作在触发前被测试桥接拦截，不发起真实续聊、GitHub 请求或测试执行。截图与结果保存在输出的独立目录，正式保留为验收材料。
- 字符预算回归使用最终 checkpoint 脚本，验证超限拒收、原稿不截断、任务仍可结算、Unicode 字符、精确边界及证据字段不能夹带正文；旧格式和旧超长报告仍进入全局复盘来源并可在生长图查看，不能用新预算删除历史证据。
- 浏览器回归使用旧版超长 summary：默认层只显示不超过 120 字符的结果预览，首次打开的最新任务直接呈现待处理事项与继续动作，完整旧 summary 仍可从“产出与依据”读取。
- 全局复盘路径回归同时写入无 `projectPath` 的 schemaVersion 2 语义处置记录，确认其进入 `candidate-decisions` 来源清单，而不是只有提示词列出目录。
- 此轮不重跑已完成的真实 CLI/手动复盘演练；前文证据仍只代表原轮范围。新字符限制由生成指令和实际接收、复盘读取路径共同验证，不以模型必然遵守指令为前提。

1000 个实际落盘任务的本地实验：首次建立报告索引约 1.23 秒，其间事件循环持续响应；下一页约 0.91 秒，仅读取数据库，不重读报告正文，每页返回 20 项。该结果是本机观察，不是所有机器上的延迟保证。

真实 CLI 证据只覆盖 Codex。其他 CLI 的任务归组、报告兼容及终端既有行为由自动测试覆盖，本轮未逐一运行其真实二进制。发布与检查结果以任务最终报告中的精确提交和既有 CI/扩展发布回读为准，不以 CI 或覆盖率代替用户目标验收。
