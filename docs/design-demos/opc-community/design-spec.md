# SoloMap OPC 数字社区 · 三方向设计规格

## 目标

为 SoloMap 官网从“第二个工作台”转向“OPC 数字社区”制作三套可直接在浏览器查看的高保真概念稿。用户需要通过真实页面效果判断方向，不需要先理解实现方案。三版共用同一产品事实、品牌资产和核心内容，只改变视觉语言、构图与首页入口重心。

## 产品与用户

SoloMap 是面向使用 AI Agent 构建产品的独立开发者的本地优先项目推进工具。本地插件继续掌握项目事实、路线图、Agent 执行与验证结果；官网社区只承接用户主动公开的脱敏项目卡点、临时共创、可复用能力和已确认贡献，不成为云端项目副本。首页主要面对正在独立做产品、缺少产品反馈、测试者、领域经验或分发协作者的 OPC 创业者。

## 用户要完成的动作

1. 第一眼理解：这里聚集的是正在推进真实项目的人，不是泛创业论坛。
2. 发布一个脱敏项目卡点，说明目标、问题和需要的帮助。
3. 浏览其他项目的具体求助，并选择自己能贡献的部分。
4. 进入临时共创空间，围绕一个问题形成输入。
5. 发现经过真实项目采用的 Skill、模板、工作流或方法。
6. 理解有效贡献会回到本地项目形成下一步或结果。
7. 在需要时安装 SoloMap，回到本地推进自己的项目。

## 首页内容骨架

- 顶部品牌与导航：正在求助、共创空间、能力库、OPC 实战、安装 SoloMap。
- Hero 核心句：“一个人做公司，不必一个人解决所有问题。”
- 解释句：项目留在本地；只把当前需要帮助的问题带到社区。
- 主动作：“发布一个项目卡点”；次动作：“看看谁需要帮助”。
- 项目求助区：呈现真实语气的脱敏问题，不展示虚构统计、粉丝数或点赞数。
- 社区闭环：卡点 → 贡献 → 带回本地 → 可验证结果。
- 能力区：路线图模板、Agent 工作流、发布清单等可复用对象。
- 本地优先承诺与安装入口。

## 文案与内容约束

- 所有可见文案直接面向独立开发者，不出现“对象模型、数据投影、MCP、内部治理”等工程词。
- 不编造用户数量、活跃度、交易额、成功案例或真人身份。
- 原型中的项目卡点属于概念内容，不给出虚假点赞、回复和浏览数字。
- 不使用 Lorem ipsum，不用 emoji 充当图标。
- 核心表达必须是“项目推进”，不是“多认识人”或“刷内容”。

## 三个方向

### A · 复古未来项目星图

秒数轮盘命中网页风格第 7 项“Cosmic Retro-Futurism”。以奶油纸白、纯黑、钴蓝和品牌青紫为主，把项目、贡献者和能力表现为星图节点与轨迹。页面骨架为左侧宣言、右侧项目网络地图，下方进入信号式求助列表。气质应像一本关于未来协作的天文图录，而不是霓虹 SaaS。

### B · 克制知识社区

以 Are.na 的内容优先、细灰线、高密度网格与克制社区气质为现实参照。页面骨架为顶部短宣言、下方直接进入多列求助与能力内容流；低装饰、几乎无卡片阴影、强调可扫读和内容连接。不能照抄 Are.na 品牌，只迁移“内容比平台更重要”的原则。

### C · 公共文化行动板

以 Pentagram 的品牌系统方法为思维参照：用强识别的大字、公共告示板式信息层级和模块化规则，建立能长期扩展的 OPC 公共空间。页面骨架为超大标题与行动入口交错，下方用红、青、纸白和黑组成不同职责区块。气质应像一套新兴公共文化运动的身份系统，而不是常见创业社区。

## 视觉与技术规格

- 每方向一个独立纯 HTML/CSS 文件，可直接通过 `file://` 打开。
- 主要比较视口为 1440×900，完整页面可滚动。
- 需适配 375px 移动端，不出现水平滚动。
- 正文不小于 14px，标签不小于 12px，关键点击区域至少 44px。
- 使用仓库真实 SoloMap Logo；可引用同仓库真实官网/工作台截图，但不得重画产品 UI 冒充真实界面。
- 不依赖外部 JS、字体 CDN 或图片服务；离线打开也应成立。
- HTML 顶部用注释写明假设、设计理由与哪些内容是概念文案。
- 每版至少包含一个明确的 hover/focus 状态，但静态截图仍须完整可读。

## 图片判断

这个页面的主角是项目问题、贡献关系与可复用能力，摄影或生成图片不是内容必需。品牌识别依赖真实 Logo；数字产品真实性由仓库中已有的官网与工作台截图作为辅助资产，不额外抓取装饰图。
