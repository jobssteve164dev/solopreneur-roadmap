# SoloMap 四阶段视图组件设计指导

## 结论

Build -> Sell -> Learn -> Improve 是 SoloMap 的项目判断模型，不应在侧边栏做成常驻大组件。

第一版落地原则：

- 侧边栏只显示四阶段推导出的下一步和轻量缺口信号。
- 大图可以提供完整四阶段视角，用于理解、筛选和导航路线图。
- 路线图生成与调整必须把四阶段作为底层方法论，用户不需要手动维护它。

## 用户动作模型

用户打开 SoloMap 时，优先要完成的动作不是理解方法论，而是继续推进项目。

因此侧边栏的首要问题是：

- 我现在该做什么？
- 为什么是这一步？
- 点哪里可以直接推进？

四阶段只能帮助回答这些问题，不能抢走主入口。

大图的主要问题不同：

- 项目整体是否失衡？
- 哪些环节属于 Build、Sell、Learn、Improve？
- 为什么下一步需要调整路线图或补齐市场/反馈动作？

所以完整四阶段视图属于大图，不属于侧边栏首屏。

## 侧边栏设计

侧边栏项目卡片已经承载项目选择、状态、Next Action、Issue、Solo 和继续对话。不要再新增一个常驻四阶段大卡片。

侧边栏只允许出现两类轻量表达。

### 1. Next Action 文案

四阶段判断应转化成用户动作语言。

推荐：

```text
下一步：补齐分发动作
```

```text
下一步：根据反馈调整路线图
```

```text
下一步：继续完成当前构建环节
```

避免：

```text
Build -> Sell -> Learn -> Improve 健康度分析
```

```text
四阶段飞轮当前处于 Sell 缺口状态
```

### 2. 轻量阶段信号

如果需要解释推荐原因，可以在项目卡片中放一行紧凑信号。

推荐：

```text
Build 3 · Sell 0 · Learn 2 · Improve 1
```

或：

```text
Build 已推进 · Sell 缺口 · Learn 有反馈 · Improve 下一步
```

要求：

- 不超过一行或一个紧凑 2x2 微状态块。
- 不展示方法论说明。
- 不新增独立入口和复杂交互。
- 点击阶段信号时，只能打开大图对应视角或定位相关环节。

## 大图设计

大图可以显性展示四阶段，因为大图本来就是用户理解项目结构和路线图关系的空间。

建议放在路线图顶部，作为项目飞轮仪表盘，但不能压过路线图卡片本身。

```text
Build      最近交付 / 当前工程环节
Sell       最近分发 / 缺口提醒
Learn      Issues / 反馈 / 指标
Improve    当前 Next Action / 路线图调整
```

大图里的四阶段视图应承担三个动作：

1. 高亮某一阶段相关环节。
2. 展示该阶段最近证据，例如文件、Issue、运行记录或完成标准。
3. 在缺口明显时提供路线图调整入口。

它不应成为一张只读说明图。

## Next Action 推荐逻辑

四阶段最重要的落点是推荐下一步，而不是展示自己。

推荐逻辑应优先遵守现有状态顺序：

1. Running。
2. Failed。
3. In Progress。
4. 依赖满足的 Pending。
5. 全部完成后进入路线图调整或下一轮循环。

在同等状态下，四阶段用于判断项目是否失衡：

- Build 很多但 Sell 没有：推荐补齐分发、官网、发布或销售动作。
- Sell 有动作但 Learn 没有：推荐收集反馈、整理 Issue 或补指标记录。
- Learn 有反馈但 Improve 没有：推荐调整路线图或重排优先级。
- Build 当前失败：仍优先处理失败，不用强行切到 Sell/Learn。

用户看到的必须是明确动作，不是排序规则。

## 路线图生成与调整

四阶段应该进入 Agent 的路线图生成和调整提示词，但不能变成用户需要理解的表单或配置。

生成路线图时：

- 面向外部用户并需要获客、采用或转化的项目，默认覆盖 Build、Sell、Learn、Improve。
- 内部工具、迁移、研究、内容或基础设施项目，不强行套用商业化四阶段。
- 每个阶段必须落到可执行环节和可验证交付物。

调整路线图时：

- 当用户要求增加工程任务时，检查是否会长期挤压 Sell/Learn/Improve。
- 当 Issue 或反馈积压时，推荐进入 Learn 或 Improve。
- 当所有环节完成时，下一步不是停住，而是进入新一轮 Build -> Sell -> Learn -> Improve。

## 组件边界

第一版不做：

- 侧边栏常驻四阶段大组件。
- 需要用户手动配置阶段权重或健康度的表单。
- 用四阶段替代现有路线图环节。
- 在项目卡片里塞完整方法论解释。

第一版要做：

- 侧边栏 Next Action 使用四阶段缺口作为推荐原因之一。
- 侧边栏保留轻量阶段信号，最多一行。
- 大图提供完整四阶段视角和阶段筛选。
- 路线图生成/调整 prompt 使用四阶段做底层审查。

## 验收标准

- 侧边栏打开后，首屏仍然优先显示下一步动作。
- 用户不需要理解 Build/Sell/Learn/Improve 的完整方法论，也能知道下一步点哪里。
- 大图能显性查看四阶段结构，并可定位相关路线图环节。
- 四阶段缺口能影响 Next Action 和路线图调整建议。
- 没有商业化目标的项目不会被迫出现 Sell 阶段。
- UI 中不出现给维护者看的方法论说明、内部排序规则或实现细节。
